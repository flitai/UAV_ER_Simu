## 1. 目录布局（已冻结）

每个观测区域（AOI，Area of Interest）一个目录，位于 `data/scene/<aoi>/`。

| 文件 | 内容 | 来源 |
|---|---|---|
| `basemap.pmtiles` | 底图瓦片，zoom 0 至 15；建筑几何在 zoom 11 及以上 | 用 `pmtiles extract` 从本地 `planet.pmtiles` 裁切 |
| `buildings.geojson` | 建筑几何，同时驱动三维渲染与遮挡计算 | 从同一份 `planet.pmtiles` 的 zoom 15 瓦片解码 `buildings` 图层，跨瓦片合并去重 |
| `dem/` | 数字高程模型瓦片，仅用于山体阴影的视觉效果 | AWS terrarium，zoom 0 至 8 |
| `manifest.json` | 数据包清单：来源、参数、输入哈希、坐标版本、生成时间 | 建库脚本生成 |
| `quality-report.md` | 质量报告：要素数、高度来源分布、与对拍基准的差异 | 建库脚本生成 |

目录名与文件名必须是纯 ASCII，不含空格。

## 2. 建筑数据字段（已冻结）

`buildings.geojson` 的每个要素包含五个字段：

| 字段 | 含义 | 说明 |
|---|---|---|
| `id` | 建筑标识 | 后续用真实高度升级数据时，只改高度与 `src`，**不改 `id` 与几何** |
| `base_m` | 底面离地高差，单位米 | 不是海拔。禁止与数字高程模型的海拔隐式相加（铁律 2） |
| `height_m` | 建筑高度，单位米 | 同上，离地高差 |
| `src` | 高度来源标记 | 真实标注与估算值必须区分。估算值标为 `est:*`，该标记必须随字段传到每一个下游产物（铁律 14） |
| `footprint` | 底面轮廓多边形 | WGS-84 经纬度，坐标参考系 EPSG:4326 |

## 3. 渲染与物理同源（已冻结）

`buildings.geojson` 是建筑几何的**单一来源**，同时驱动三维拉伸渲染和遮挡计算的桶网格。

瓦片里的 `buildings` 图层只作为观测区域**之外**的渲染回退，**永远不进入遮挡计算**。原因是
瓦片建筑经过切割简化，且缺失高度时被填了默认值，不适合用于计算（决策 D-002）。

## 4. 已知的数据欠项

国内城市的开放街道地图（OSM）建筑高度覆盖率极低。西安 12 公里见方样本共 13593 栋建筑，
其中带 `height` 标签的占 1.0%，带 `levels` 标签的占 1.3%，96.1% 只有 `building=yes`。

这意味着首批场景包里绝大多数建筑高度是估算值，必须带 `est:*` 标记。
