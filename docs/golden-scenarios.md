# 三份基准场景：golden-01 / 02 / 03

这份文档写给两种人：要拿系统做演示的人，和想知道"这三个场景到底在证明什么"的人。
它不是格式规范——场景文件每个字段怎么写，看 `docs/scenario-format.md`；
每个环节背后的公式和参数取值，看 `models/` 下各环节的说明；
框图页怎么操作，看 `docs/chain-view-guide.md`。

## 为什么是三份

一个仿真系统最怕的事情，是画面上的数字没人能说清楚从哪来。
所以这三份场景不是"随手做的例子"，而是三把尺子，各量一段：

- **golden-01** 量的是**一条链路的物理正确性**。一架无人机、一个侦察站、一个单频信号，
  从发射功率到最后的检测结果，每一级的读数都能和课本上的公式对上。
- **golden-02** 量的是**宽带观测和数字信号处理**。两架无人机发两种不同形态的信号，
  接收机一次看八兆赫兹，链路上接进滤波、下变频、信道化三级处理，验证它们不会把信号弄坏。
- **golden-03** 量的是**多站协同**。三个站一起测向、一起定位，
  并且故意让其中一个站的时钟差一点，看它对定位精度的影响。

三份场景都放在 `data/scene/beijing-yayuncun/scenarios/`，
地理背景是同一片区域：北京亚运村周围二十公里见方，真实的建筑与路网。

## 三份的分工

| | golden-01 | golden-02 | golden-03 |
|---|---|---|---|
| 场景名 | 亚运村上空单机过顶后远去 | 亚运村宽带观测：图传与跳频遥控 | 亚运村三站三源：交叉定位与时差定位 |
| 规模 | 一站一机 | 一站两机 | 三站三机 |
| 接收机 | 窄带：每秒五十万点、带宽 400 kHz | **宽带：每秒一千万点、带宽 8 MHz** | 窄带，与 golden-01 相同 |
| 无人机发什么 | 一个单频信号 | 一路图传（带限噪声）＋一路跳频遥控 | 两路同频单频信号 ＋ 一路突发 |
| 场景时长 | 三分钟 | 三十秒 | 两分钟 |
| 一句话概括 | 每一级电平都对得上公式 | 宽带里两种信号分得开、降得下来 | 多站定位，以及时钟质量的代价 |

# golden-01：一架无人机过顶后飞远

## 场景讲的是什么

亚运村中心架着一部侦察接收机，天线高三十米。
一架多旋翼无人机从它西南方约两百米处起飞，向东北方向飞，
第十五秒前后几乎从站点正上方掠过（这时斜距只有七十米左右），
然后一路飞远，三分钟后距离站点三公里。

无人机全程在 2440.5 MHz 上发一个单频信号，发射功率 27 dBm（半瓦），
这是 2.4 GHz 图传下行的一个简化模型。

于是整个场景就是一件事：**距离从七十米变到三千米，接收到的信号跟着变弱。**
自由空间路损从 77.1 dB 涨到 109.9 dB，接收电平从 −45.1 dBm 掉到 −77.9 dBm。

## 它要证明的事

这个场景的价值在于，上面那条"距离变大、信号变弱"的因果链，
中间每一环都能单独拿出来和公式核对。系统会在链路的六个位置摆观测点：

| 观测点 | 位置 | 这里应该读到什么 |
|---|---|---|
| S0 辐射源输出 | 无人机刚发出来 | 就是场景里写的发射功率，27 dBm |
| S1 接收天线端 | 电波走完全程、刚被接收天线收下 | 发射功率 ＋ 两端天线增益 − 路损 |
| S2 前端输出 | 过了接收机射频前端 | 比 S1 高出一个前端增益（20 dB），同时噪声底浮起来 |
| S3 量化后 | 模数转换之后 | 多出量化噪声，并记录有没有削波 |
| S4 主产品 | 下变频之后、信道化之前 | 本系统对外交付的主要数据产品 |
| S5 子信道 | 信道化之后 | 切出来的某一路子带 |

实测下来（这些都是原型阶段的验证值，不是交付指标）：

- 无人机三个时刻的位置，和独立算出来的航迹基准**完全一致**（判据是百万分之一度）。
- 两个时刻之间的带内功率差，和几何算出来的路损差**只差 0.074 dB**，判据是 0.5 dB。
- 绝对的链路预算在三个点上**偏差不超过 0.021 dB**。
- S0 读到 **27.0000 dBm**，一位不差；S1 和链路预算**差 0.081 dB**；
  S2 减 S1 **正好是 20.000 dB**，就是前端增益。
- S2 的噪声底和热噪声公式（−174 dBm/Hz 加噪声系数，再按带宽折算）**差不到 0.05 dB**。
- 单音的频率位置**偏 142 Hz**，这不是误差而是多普勒频移，理论值是 142.4 Hz。
- 跑完整条链，检出率 1.0、虚警率 0.0014、发现时延 0、识别准确率 1.0。

一句话：这个场景在证明**画面上的每个数字都是算出来的，不是摆出来的**。

## 演示怎么走

**第一步，从场景页开始。** 地图上是真实的亚运村，一架无人机沿航线飞。
右栏常驻一张目标卡片，写着它到站点的距离、接收电平、信噪比。
拖动底部的时间轴，无人机位置和这三个读数同时跟着走。
这里值得说的一句是：**读数不是预先算好的一张表，是按场景几何实时算出来的。**

**第二步，切到框图页。** 屏幕上是一条固定的处理链，十一张卡片依次排开：
辐射源 → 发射天线 → 传播信道 → 接收天线 → 接收机前端 → 模数转换 → 数字下变频 →
信道化 → 检测识别评价 → 测向 → 多站定位。
接收滤波挂在接收机前端那张卡里，特征提取、模板识别、评价三件挂在检测识别评价那张卡里。
点任何一张卡，右栏就给出它的参数；上方的频率计划面板有十四项检查实时判对错，
比如采样率够不够、抽取比整不整除、目标信号会不会落到带外。

**第三步，勾上 S0 到 S3 四个观测点，点运行。**
结果页的信号页签里可以逐个观测点看过去：
S0 读到 27 dBm，S1 读到链路预算算出来的值，S2 整体抬高 20 dB 而且噪声底浮起来。
**这是整个演示里最值得花一分钟的地方**——一条链上四把尺子，每把都对得上一个公式。

**第四步，看结果页的检测识别。** 三行时间线上下对齐：
最上面是真值（信号什么时候真的在发），中间是检测器判出来的突发，下面是识别给出的标签。
右边的指标卡给出检出率、虚警率、发现时延和识别准确率。

**第五步（可选），看建筑遮挡。**
默认的传播模型只算自由空间损耗。换用 `tests/regression/diagrams/chain-golden-01-e3.json`
这份配套框图，传播模型会把亚运村四万多栋真实建筑算进去，画面上立刻不一样：
起飞时无人机被楼挡住，附加损耗 36.98 dB；第 7.2 秒到 26.4 秒之间升高到能看见的高度，
这一段是视距；飞远之后重新被楼挡住，附加损耗 32.30 dB。
最末端的带内信噪比从 33.7 dB 掉到 **1.4 dB**——从"看得清清楚楚"掉到"勉强能发现"。
这三段式是算出来的：站点天线才三十米高，周围的楼比它高。

## 演示时容易讲错的地方

**任务跑完的状态是"降级"不是"正常"，这是对的。**
默认参数下模数转换有 6.09% 的样点削波。这是引擎如实做出的判断，
我们有意没有为了画面好看去调默认参数。
这里还有两件事要分开说：削波次数本身只是一个**数据标记**，记在产品索引里，
观测点的数据状态仍然是正常的；只有削波比例超过设定门限，
才会把"模数转换"这个**环节**标成降级。

**不要用这个场景演示下变频和信道化。**
每秒五十万点的采样率下，抽取比只能取一，抽取无从谈起；
切成四条子信道之后每条只剩 ±50 kHz 可用，而目标信号占 400 kHz。
默认链路有意不接这三级，要看它们请用 golden-02。

**打开建筑遮挡之后链路线会变红，那是如实反映不是报警。**
红色表示"这条链路在几何上被楼切断了"，和损耗大小无关——
擦着楼顶过去只损失几分贝，也算非视距。

# golden-02：宽带里同时看两种信号

## 场景讲的是什么

还是亚运村，还是一个站，但接收机换成宽带的：每秒采一千万个点，一次看八兆赫兹。
天上有两架无人机，发的东西完全不一样：

**一架发图传。** 这是下行的视频链路，占用一块连续的 2 MHz 频段
（2437.5 到 2439.5 MHz），在频谱上是一整块。

**另一架发跳频遥控。** 这是上行的控制链路，每十毫秒换一个频点，
在五个频点之间循环（2440.125 到 2443.4375 MHz 之间），每个频点上发一个短脉冲。
停留时间和脉冲周期恰好相等，所以**一跳正好一个突发**。

时间上是有意错开再叠起来的：第 0.5 到 2.5 秒只有图传，
第 3 到 4.5 秒只有跳频遥控，**第 5 秒开始两个一起发**。

## 它要证明的事

这个场景撑起三件在 golden-01 里做不到的事。

**第一，宽带里能同时看见两种形态完全不同的信号。**
图传在瀑布图上是一条粗带，跳频遥控是五列跳动的短点。
它们在频率上不重叠，所以能一眼分开。

**第二，信号的开关和跳频是按采样点精确施加的，不是按数据块粗略近似的。**
实测跳频突发的起始位置和时间表**偏差 0.0 纳秒**，
而系统里一个分析帧的长度是 102.4 微秒——也就是说精度远远高于观测的分辨率。
这件事重要，是因为如果开关只能落在数据块边界上，
换一个块长信号就变了，那整套结果就不可复现。

**第三，数字信号处理接上之后，信号内容不会被改坏。**
这是最容易被怀疑的一点：加了滤波、下变频、信道化之后，读数还能信吗？
实测答案是能——下变频前后带内功率**差 0.064 dB**，
信道化前后**差 0.065 dB**，三级全开串起来累计**只差 0.002 dB**。

另外几个验证值：带限噪声的 −3 dB 带宽实测 1.9727 MHz，设定值是 2 MHz；
突发的导通时间占比实测 0.3043，设定值是 0.3；
跳频遥控被识别成"遥控跳频"这一类，共 180 行，准确率 1.0。

## 演示怎么走

**第一步，先讲时序。** 在瀑布图上，三段一眼就能分出来：
先是一条粗带单独出现，然后消失、换成一串跳动的点，最后两者同时在。
拖时间轴过去，能看到每一段的起止都和时间线对得上。

**第二步，讲两种信号形态的差别。**
图传是连续发射、占一整块带宽，属于"能量一直在那儿"的信号；
跳频遥控是短促、间歇、频率不断变化，属于"抓不住就没了"的信号。
反无人机侦察要同时应付这两类，这正是宽带接收的意义。

**第三步，演示三级数字处理。** 默认链路不接这三级，需要换配套的框图文件：

| 框图文件 | 做了什么 | 画面上看到什么 |
|---|---|---|
| `chain-golden-02-ddc.json` | 下变频：中心频率移到 2438.5 MHz，采样率减半 | 主产品的采样率从每秒一千万点降到五百万点，图传被搬到中心 |
| `chain-golden-02-chan.json` | 信道化：把 10 MHz 切成四条 2.5 MHz，取中间那条 | **两个信号被分开了**：图传整个落进旁边那条子信道，本路只剩三个跳频点 |
| `chain-golden-02-dsp.json` | 三级全开：滤波 → 下变频 → 信道化 | 每秒一千万点降到五百万、再降到二百五十万，三个观测点一次给出三种采样率 |

这三份的意义是：**侦察接收机拿到一大片频谱之后，怎么一层层缩到感兴趣的那一小段。**

**第四步，如果被问到性能。** 三十秒场景跑二十秒、每秒一千万点、启用下变频，
墙上时间 30.86 秒，也就是实时率 0.648。这是单线程的原型实现，还没有做并行优化。

## 演示时容易讲错的地方

**第 5 秒之后两个信号被合并成一个，这是有意保留的已知边界。**
每个站只配了一个单频段能量检测器，当两个信号同时出现在它的观测带内，
它会把它们当成一个持续的突发（实测有一段横跨第 5 到 6 秒，
把一百个跳频突发全吞了进去）。要分开需要子带检测或多通道，那是后续工作。
**这一条写在模型说明里，不是缺陷，演示时可以主动讲，正好引出后续要做什么。**

**"突发级 252 对 252 全部匹配"和"识别准确率 1.0"不是一回事。**
前者说的是检测出来的突发都对上了真值；
后者的分母只包含那些既产出了识别结果、又匹配上真值的段。两个数字的分母不同。

**第一个跳频突发能判对，靠的是场景顺序。**
识别算法会参考"上一段是什么"，图传先发，正好当了这个参考。
如果换成跳频先发，第一段会落到"无法确定"。这是算法的已知特性。

**信道化那份里，图传被压下去的 25.6 dB 不是信道化的功劳。**
那是发射端本身的滤波器裙边定的——在量化后那个观测点上读同一段频率，
得到的是同一个数，只差 0.04 dB。同理，那份配套框图的虚警率是 0.52，
原因是图传的裙边把本路的带内功率抬高了 10.5 dB，检测器照样触发，
而图传的真值在观测带之外不计入分母。这是发射端滤波不是理想砖墙的真实后果，
我们没有为了指标好看去掩盖它。

# golden-03：三个站一起定位

## 场景讲的是什么

三部侦察接收机摆成一个边长约 2.2 公里的等边三角形，都架在三十米高度，
外接圆半径 1270 米。天上有三架无人机：

- **一架穿越**：从西南飞到东北，横穿三角形。
- **一架绕飞**：围着中心转圈，第 30 秒关机、第 40 秒重新开机。
- **一架悬停**：停在东南站附近不动，发间歇突发。

**前两架故意用同一个中心频率、同一个频偏**，也就是说它们在频谱上完全重叠。
这是刻意设计的，用来演示同频多目标会给测向带来什么麻烦。

地图上还画了一个半径四百米的圆形告警区。

三个站的时钟质量是有意做成不一样的：
北站同步误差 3 纳秒、处于锁定状态；西南站 5 纳秒、锁定；
**东南站 10 纳秒、处于保持状态，而且带一个 20 纳秒的固定偏差。**

## 它要证明的事

**第一，多个信号在接收天线上是线性叠加的。**
两个同频信号合成之后的功率，和两条链路预算分别算出来再相加的结果
**只差 0.001 dB**；三个信号逐站叠加的偏差不超过 0.013 dB。

**第二，测向的误差模型是可信的。**
系统给出的每个测向结果都带一个误差范围。跑蒙特卡洛统计下来，
实际误差的分布和声称的误差范围**只差 0.80%**（判据是 3%）。
换句话说，**它声称的精度和它实际的精度是一致的**——这比精度本身高低更重要。

**第三，两种定位方法都能用。**
交叉定位（比较各站测到的方向）的置信椭圆，实测有 87.0% 的解落在里面，
理论值是 86.5%；时差定位（比较信号到达各站的时间差）的中位误差是 7.95 米。

**第四，时钟质量直接换算成定位误差。**
东南站那 20 纳秒固定偏差，相当于 6 米的距离差，
使得时差定位的结果整体偏了 4.4 米。把这个偏差扣掉之后，
落在置信椭圆里的比例从原先的偏低回到 87.5% 和 86.5%。
**这正是这个场景要讲的一条工程结论：随机的同步抖动可以用协方差描述，
而一个没标定的固定偏差不能——它会整体拖偏，而且统计指标上看不出来。**

## 演示怎么走

**第一步，场景页一打开右栏就是满的。**
三架无人机、三个站，每个目标一张卡片，卡片里每个站占一行：
到这个站的距离、这个站收到的电平、信噪比，
第二行是这个站测到的方向和误差范围、以及测向质量档位，
再下面一行是三站融合出来的定位结果。
这里可以强调一句：**卡片上只摆事实，不写"威胁度 85%"这种没有出处的数字。**

**第二步，看地图上的六样东西。**
从站点指向目标的测向扇形（越远越淡）、定位结果的误差椭圆
（交叉定位和时差定位用两种颜色区分）、目标图标带选中环、
站点到目标的连线上标着距离、目标下方的高度立柱、以及红色的告警圈。
非焦点目标会自动压淡，否则九条测向扇形会叠成一片什么也看不清。

**第三步，等绕飞那架进圈。** 它进入告警区的一刻图标换成红环。
告警区是整个系统里"威胁色"的唯一来源——
颜色只在进出一个明确定义的区域时才变，不做没有依据的威胁度推断。

**第四步，拖时间轴。** 目标图标、测向线、定位椭圆、信号游标同时跟着动，
空格键可以连续回放。

**第五步，比较两种定位方法。**
换用 `chain-3x3-aoa.json` 看交叉定位，`chain-3x3-tdoa.json` 看时差定位，
同一个场景两套解，可以直接比椭圆的大小和形状。

**第六步，讲时钟。** 指出东南站的时钟处在保持状态、带固定偏差，
再指出它的定位解整体偏向哪一边。这是一个很好的切入点，
用来说明为什么多站系统对时统的要求那么高。

## 演示时容易讲错的地方

**有两个站的检出率接近零，这是已知边界不是故障。**
三架无人机都从第 0 秒起就在持续发射，而检测器用的是滑动噪声估计——
它靠"最近一段时间的背景"来定门限，当信号从头到尾一直在，
它就把信号本身当成了背景。评价模块如实把这记成漏检，没有掩盖。
**golden-01 那种"先安静一会儿再开机"才是这类检测器的正常工作条件。**
要处理持续信号需要别的手段，那是后续工作。

**虚警率那一列整列是空的。** 因为真值覆盖了全部时间，
根本不存在"信号不在、检测器却报了"的样本，分母为零。
系统的做法是把这一列留空并写明原因，而**不是把空当成零**填进去。

**混淆矩阵会很难看。** 实测是"信标类 87 段里，47 段判成了遥测、5 段判对、35 段判成未知"。
逐类统计里还会出现某一类样本数为零、精确率却写着 0.0 的情况。
原因是这个场景本来就难：窄带观测下三个信号挤在同一个频点上，
识别拿不到足够的区分特征。**这个数字难看是它应该难看，
拿它来说明"识别在什么条件下会失效"比拿一个漂亮数字有用。**

## 一段值得讲的移植经历

交叉定位的几何质量分级，原先的实现是按三条测向线之间的**最大**张角来分档的。
这会把"两条几乎平行的线加一条好线"判成几何良好，
而那批解实际上只有 45% 落在置信椭圆里。
后来改用**最小的两两交会角**作为降级判据——
原实现的参数名本来就叫"最小交会角"，比的却是最大张角。
改完之后，判为有效的那一档，落在椭圆里的比例回到 87.0%。
原来的分级函数一个字没动，因为它被一批基准数据钉着；
新判据是加上去的，不是改出来的。

# 三份共同的约定

**都是合成场景。** 站点位置、航线、发射功率、天线增益、噪声系数
都是 2.4 GHz 图传与遥控的通用取值，不是任何一份真实设备清单。
它们属于原型阶段的取值，等拿到实测数据后会按同一套脚本重新标定。

**界面上不解释这些。** 系统不会在画面上标"这是合成数据"或"这个高度是估算的"。
这类标记留在数据层，随每一份产物传下去；要查来源，在网址后面加 `?dev=1` 打开开发者模式。
这是有意的设计：演示系统应该看起来像交付系统，而不是像实验记录。

**三份都是只读的。** 每一份都钉着一份独立算出来的航迹基准和若干套配套框图，
改动一个字节就是一次正式的基准变更，要重新生成基准、重新核对全部下游结果。
所以界面上对这三份场景只提供"另存为"，直接改写会被服务端拒绝。
**要改参数做演示，先另存成工作副本，在副本上改。**

**信号频率都选在频点格的中心上。** 系统做频谱分析时把带宽切成 1024 个格子，
每格约 9.77 kHz。三份场景的信号频率都精确落在某个格子的中心：
golden-01 的偏移 48828.125 Hz 在 1024 格和 4096 格两种设置下都居中，
golden-03 的 −97656.25 Hz 正好是往下数 200 格，golden-02 的五个跳频点每隔 32 格一个。
这样读出来的电平不会因为信号落在两格之间而偏低，量到的就是真电平。

**同一个随机种子跑两遍，产出的数据文件完全相同，一个字节都不差。**
这是可复现性的底线：任何一次结果都应该能被别人在别的机器上重现出来。
种子在框图页的「试验设置」里设，管的是接收机热噪声、统计阴影、测向误差抽样和站钟抖动；
换一个种子，这些随机量全变，而场景几何、发射功率、路损这些确定性的量一个都不动。
（场景文件里也有一个 `seed` 字段，但它目前没有消费者，见 `docs/scenario-format.md`。）

# 怎么跑起来

从界面上：场景页左栏顶部的"场景"下拉框里选一份（三份都标着"基准 · 只读"），
框图页和结果页会跟着切过去。

从命令行：

```bash
# 只跑运动学，看无人机的航迹事件流
engine/build/cuav_run --scenario-track \
  data/scene/beijing-yayuncun/scenarios/golden-01.scenario.json

# 跑一条完整的处理链
engine/build/cuav_run --run tests/regression/diagrams/chain-golden-02-dsp.json \
  --out data/runs/<任务标识> \
  --scenario data/scene/beijing-yayuncun/scenarios/golden-02.scenario.json
```
