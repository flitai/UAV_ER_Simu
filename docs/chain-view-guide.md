# 框图页操作说明与约束

> **性质**：面向使用者的操作说明，不是规范。设计依据是 09 报告 §6、10 报告 §5、12 报告 §5；
> 实现是 `web/src/chain/`。本文只写**当前实现真正做到的行为**；设计里已定但尚未实现的，
> 集中列在第 5 节，不与已实现的混在一起。
>
> **2026-09-10（D-060）本文全篇改写。** 原名《框图画布操作说明与约束》，讲的是自由画布——
> 那个形态已经删掉（用户原话：「自由画布不重要，用户操作起来也很难控制，有点华而不实」），
> 框图页现在只有**典型链路视图**一种形态。画布时代的操作说明（拖放、连线、组件库、
> 端口把手形状）随之作废，不在本文保留；要看它写过什么，翻 git 历史里的
> `docs/diagram-canvas-guide.md`。

**入口**：地址 `#/diagram`，顶栏「框图」页签，或 `Alt+2`。框图页没有第二种形态，
旧地址 `#/diagram/canvas` 仍然落在这一页，地址栏会被规范回 `#/diagram`。

## 1. 一条贯穿始终的原则

**界面不自行解释任何规则。** 组件有哪些、参数是什么类型与单位、取值范围多少、缺省值是什么，
全部来自引擎生成的组件目录（`GET /api/v1/components`，由 `cuav_run --catalog` 导出）。

对使用者的实际意义是：**界面上填得进去的，引擎就一定认；界面拒绝的，引擎也一定拒绝。**
不存在「界面允许但提交后报错」的情形。唯一的例外是需要跨节点或跨文件才能判断的检查
（场景哈希、时长关系等），那些由提交时的 `cuav_run --validate` 完成，见第 4 节。

## 2. 这一页是什么

一条**固定的十一环节链**：

```
辐射源 → 发射天线 → 传播信道 → 接收天线 → 接收机前端 → ADC
      → DDC → 信道化 → 检测识别评价 → 测向 → 多站定位
```

卡片按蛇形排布（第一行从左往右，第二行从右往左），一行读到头下一张卡片就在正下方。

**你能做的**：改参数、勾观测点、选信号源模式、选场景与参与的站点和目标、勾旁路。
**你不能做的**：增删环节、改连线顺序——这条链的形状是固定的（04 §5.1 的端到端对象）。

### 2.1 试验设置（左栏）

| 项 | 说明 |
|---|---|
| 模式 | 全合成 / 实测回放 / 混合增强。**它同时决定辐射源那个环节用哪个零件**，卡片上因此没有第二个开关（D-057） |
| 场景 | 换场景等于换了一批站点与目标，旧的选择作废、由缺省全选重填 |
| 站点 / 目标 | 各是一组复选框。K 个站各跑一条接收链，N 个目标在接收天线后叠加成一路 |
| 时长、种子 | 同种子逐位可复现（铁律 9） |

下面是**频率计划**：采样率、观测中心、S4 采样率三个读数，加十一项自动检查。
检查不全过时运行按钮不可用，每一项都写清楚了怎么改。

### 2.2 配置焦点（中栏上方）

两个下拉：选哪一架无人机、哪一个侦测站。**它们只切换「现在配谁」，不改变谁参与运行**
——参与运行的由左栏的复选框决定。

参数按归属分三种，面板上会写明：

| 归属 | 哪些环节 | 说明 |
|---|---|---|
| 无人机 | 辐射源、发射天线 | 同一架机对 K 个站是同一副天线 |
| 侦测站 | 接收天线及其后 | 同一个站对 N 个目标是同一副天线、同一台接收机 |
| 全图共用 | 传播信道、多站定位 | 不随上面两个下拉变化 |

参数多于一个实体时，每行右侧多一个范围下拉：**共用 / 同型号 / 单独**。
「同型号」按场景里的 `equipment_model` 分组。

### 2.2b 三处选择各管什么（D-064）

- **左栏「站点 / 目标」勾选**：谁**参与这次计算**。勾几个站就有几条接收链，勾几个目标它们的信号就在接收天线后叠加。
  用途是在同一个场景里挑一个局部来算、看或调试。改它会改框图的形状，但不改下面的焦点。
- **中栏「当前链路」两个下拉**：框图现在**显示并编辑**的是哪一条链（哪架无人机到哪个站）。卡片上的参数摘要、
  右栏面板、「待填」都按这条链的实体算。候选只列已勾选的实体；单站单机时各只有一项。
- 卡片上**不标 ×N**：一个环节在多站多源下展开成几份是编译的事，页面上永远只看一条链。

### 2.3 参数面板（右栏）

**版式（2026-09-13 改版）**：右栏三张卡（槽位标题与归属、设备参数 · 来自场景、模型参数）用同一套行网格——
标签列固定宽、控件占满、单位与来源标记跟在控件后面。参数标签是中文短名（`web/src/chain/paramLabels.ts`），
英文标识、目录里的说明与取值范围收在标签的悬停提示里；模板固定的参数合成一行写在「模型参数」标题下。
数值框显示的是**无损**的工程计数（1024 显示 `1.024k`），点进去不改再点出来不会写回任何东西。

- **数值框接受工程计数法**：`2.44G`、`500k`、`20M`、`1e6`、`6.1u` 都可以，底层一律存 SI 基本单位。
  输入不合法时输入框标红，不会猜。
- **清空一个数值框即回到缺省值**，此时显示为浅色，且该键不会写进框图文件。
- **必填且没有缺省值的参数**会在面板上方标「待填」，卡片角标显示「待填」。
- **有三类参数不由你直接填**，面板上各自注明来源：
  - 「模板固定」——这个环节在本链里恒定的取值；
  - 「由频率计划派生」——一处填、多处派生（采样率、总样点数、观测中心频率等）；
  - 「来自场景」——真理源在场景文件里（天线增益、噪声系数），在上面的「设备参数 · 来自场景」
    那一组里改，改的是场景，随后自动保存。
- **实测录音用挑单选，不用手敲标识**（D-056）。可以按机型、批次、视距、距离筛。

### 2.4 传播效应

「传播信道」卡片上写的是**这一档包含哪几项效应**，不是某个模型的名字。点开它，
右栏多一个「传播效应 · 全图共用」分组：

| 档位 | 算什么 |
|---|---|
| **E1 快速抽象**（缺省） | 自由空间路损 + 多普勒 + 时延 |
| **E2 工程** | 再加地面双径 **或** 城市经验（二选一）、统计阴影、大气与降雨，各可单独开关 |
| **E3 精细机理** | 建筑遮挡与刀口绕射。**下拉里有但不可选**，写着「待 D3（切片 ⑤）」 |

三条要点：

- **选 E2 才出现别的开关**。E1 档下只显示档位一项——十五行参数一次全摆出来找不到东西。
- **地面双径与城市经验是单选，不是两个勾选框**。两者都自带基础损耗，同时开就把自由空间算了两遍。
  城市经验取「均值 + 分位裕度」时它已经含了阴影，此时再勾统计阴影会当场说明并挡住运行。
- **距离不用填**。它由航迹每秒重算 20 次；手填固定距离的那个变体已经撤掉（D-059）。

公式、参数来源与适用范围见模型卡 `models/channel/README.md`。

### 2.5 观测点

链条下方一行复选框，六个位置：`S0 辐射源输出`、`S1 接收天线端`、`S2 前端输出`、
`S3 量化后`、`S4 主产品`、`S5 子信道`。勾上的在下次运行时产出频谱与包络，在结果页按观测点分开看。

- 所在环节旁路或未实现时该观测点**置灰禁用**，不隐藏。
- **勾选只改框图，不动已经跑完的任务**。与当前任务不一致时工具条会提示要重新运行。
- 产品有「频谱」「包络」两项，**「IQ」本版本不产出**，原因见第 5 节。

### 2.6 运行与保存

工具条「运行」按钮或 `Ctrl+Enter`。提交前服务端会同步跑一次引擎的 `--validate`：
通过则建任务并开始跑，不通过则不建任务，错误列在链条下方。

**错误定位**：每条错误带错误码、节点标识与端口，**会落到对应的那张卡片上**并标红。
传播效应的报错虽然出在隐含的场景参数源节点上，也会按参数名反查回「传播信道」卡片。

「保存」或 `Ctrl+S` 写到服务端 `data/diagrams/`；刷新页面后自动载入**最近保存的那一份**。

### 2.7 撤销与重做

改参数、勾观测点、换模式都进撤销栈，栈深 50。

> `Ctrl+Z` / `Ctrl+Y` **尚未接到框图上**（09 §11 有约定，实现待补）。

## 3. 快捷键

| 键 | 作用 |
|---|---|
| `Alt+1 / 2 / 3 / 4` | 切到场景 / 框图 / 结果 / 数据中心 |
| `Ctrl+Enter` | 校验并运行 |
| `Ctrl+S` | 保存框图到服务端 |
| `` Ctrl+` `` | 收起 / 展开底部抽屉 |

输入框获得焦点时上述快捷键不生效。`Ctrl+D` 不绑定，它是浏览器的「收藏此标签页」。

## 4. 约束：界面当场拒绝的

这些在界面上就构造不出来，不必等到提交。

| 约束 | 说明 |
|---|---|
| **链的形状固定** | 十一个环节、连线顺序都是模板给定的，增删不了 |
| **只有 DDC 与信道化可旁路** | 别的环节没有旁路开关 |
| **至多一个替代型传播主模型** | 地面双径与城市经验做成单选（12 §2.2 闸一） |
| **同源双计当场报错** | 城市经验带分位裕度 + 统计阴影（12 §2.2 闸二） |
| **多源多站上限 8** | 固定可选口就八个（D-053） |
| **内部参数不出现** | 文件路径一类由服务端注入，界面不显示也不写进框图文件（D-037） |

## 5. 限制：当前实现做不到的

以下不是缺陷，是首期的边界或尚未排期的功能。**使用前需要知道**。

### 5.1 没有自由画布

框图页只有典型链路一种形态（D-060）。要搭模板之外的图，本版本只能手写框图 JSON 再经
`PUT /api/v1/diagrams/{id}` 存进去（刷新后会被载入，但页面只能只读展示它，见 §5.2）。
画布是否再做、做成什么样，等这条固定链路把完整流程跑通之后再定。

### 5.2 不是典型链路的框图只能只读看

载入的框图若解不成这十一个槽位（手写的，或自由画布时代存下来的），页面会说明情况、
**把原文只读摆出来供拷走**，并给一个「新建典型链路」的按钮。
**不硬解、不改写你的文档**（铁律 15）——但也编辑不了，编辑得回到手写 JSON 那条路。

### 5.3 传播信道里没有建筑遮挡与绕射

传播效应可以选到 E2，**E3 的建筑遮挡与刀口绕射未实现**，下拉里置灰写着「待 D3（切片 ⑤）」。
由此还有两处连带：视距判定恒为「视距」，所以阴影标准差表的非视距一列与测向误差预算里的
非视距多径项本期都取不到。**选了「城市」环境不等于做了遮挡判定**——城市经验模型加的是
统计意义上的城市附加损耗，不看任何一栋楼的几何。

### 5.4 DDC 与信道化未实现

两个环节的组件还没有（等 MATLAB Coder 产物），卡片上写着原因，缺省旁路。
因此 S2 / S3 / S4 三个观测点当前读数相同——这是「DDC 与信道化没做」的真实后果，不是缺陷。

### 5.5 观测点的「IQ」产品不可选

引擎本版本不产出原始 IQ 产品，对含 `iq` 的框图会明确报错而不是静默忽略（D-040 ③）。
结果页的 IQ 散点也因此没有数据源。落盘格式定稿后放开。

### 5.6 检测识别评价只到检测

检测已落地（C-3，2026-09-12，D-063）：典型链路里的能量检测器**模板固定**为滑动噪声估计
（`noise_mode = sliding`，卡片上写出来但不给改——静态门限不是交付形态，D-026），只纳入未命中帧
（删截），门限随背景漂移；命中帧按 `merge_gap_frames` 并成突发。每站一个检测器，行里带站点标识。
可改的参数：`nfft`、`pfa`、`noise_window_frames`（滑动窗长，帧）、`merge_gap_frames`、`band_power_dBm`；
`noise_frames` 只对 `probe` 模式有意义，典型链路里不起作用。结果页「检测识别」页签列出突发；
信号页页脚「叠加检测」把突发画到瀑布上。

两条已知行为（模型卡 `models/detection/README.md`）：从仿真一开始就持续发射的目标会被噪声估计
吸收、不会被检出——参考噪声必须有一段无信号的窗口（示例场景 `demo-01` 的无人机 3 s 才开机，
正是为此）；噪声估计窗 W 帧之内的虚警率高于目标值，暖机期的零星命中是正常的。

`FeatureExtractor` / `TemplateClassifier` / `Evaluator` 三件待 C-4 / C-5，结果页的「评价」页签也随之待建。

### 5.7 场景实体下拉依赖场景已载入

场景**列表**总是可选，但**实体与站点的标识**只有该场景已经载入时才有。
首期只有几个演示场景且开页面时会自动载入，通常感觉不到。

## 6. 出问题时怎么查

| 现象 | 先看哪里 |
|---|---|
| 运行按钮点不动 | 左栏频率计划里哪一项是红叉，说明文字里写了怎么改 |
| 卡片角标是「待填」 | 点开它，右栏面板上方列出缺哪几个参数 |
| 卡片标红 | 链条下方的错误列表，每条带错误码与节点标识 |
| DDC / 信道化卡片没有徽标，只写「本期旁路」 | 这两个环节本期旁路、信号直通，S4 直接取 ADC 输出；卡片不标「未实现」，也不写等哪一步（2026-09-13 用户要求；界面不解释未完成，D-039） |
| 页面说「不是典型链路」 | §5.2 |
| 结果页看不到刚勾的观测点 | 观测点改动要**重新运行**才生效，工具条会提示 |
| 想看引擎到底收到了什么 | 任务目录 `data/runs/<任务号>/diagram.json` 与 `events.jsonl` |
