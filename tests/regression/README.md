## 四、回归框图夹具

`diagrams/` 下的框图是**回归夹具**：它们不是算例本身，而是「这一形状的框图仍然装得进引擎」
的守卫。改了框图格式、组件目录或典型链路的编译规则之后，`cuav_run --validate` 跑一遍
这几份，能立刻看出有没有把既有形状改坏。

| 文件 | 形状 | 覆盖的东西 |
|---|---|---|
| `chain-3x3-aoa.json` | 3 源 × 3 站 + 测向 + 交叉定位，58 节点 108 连线 | 实例后缀 `__`、`Superposition` 八可选口、双绑定的场景绑定信道、`DirectionFinder` 的 `scene1..3`、`MultiSiteLocator` 的 `b1..3`、按站实例化的观测点、按站绑定且模板固定 `noise_mode = sliding` 的检测器 `det__<site>`（C-3，D-063）、挂在检测识别评价卡片里按站各一份的特征提取器 `feat__<site>`、识别器 `rec__<site>`（C-4）与评价器 `eval__<site>`（C-5：吃本站检测行 + 识别行 + 三路链路帧 `scene1..3`） |
| `chain-3x3-tdoa.json` | 同上但方法为 `tdoa`，61 节点 120 连线 | 另加隐含的 `toa__<site>` 节点与 `t1..3` 连线 |
| `chain-demo-02.json` | 宽带单站两源，10 MS/s（C-8） | 带限噪声图传 + 五点跳频遥控；标准算例 2、3 在它上面量 |
| `chain-demo-02-ddc.json` | 同上但启用 DDC，10 → 5 MS/s（M-2） | 数字下变频进典型链路 |
| `chain-demo-02-chan.json` | 同上但启用信道化，10 MS/s 切 4 条取零频那一路（M-3） | 多相信道化进典型链路；演示「把两个辐射源分开」 |
| `chain-demo-02-dsp.json` | 三级 DSP 全开，10 → 5 → 2.5 MS/s（C-10） | 接收滤波 → DDC → 信道化；标准算例 5、7、8 在它上面量 |
| `chain-synthetic.json` | 全合成，demo-01，20 s，S0–S3 四个观测点（C-11） | 电平链、ADC 量化与削顶、同种子复现 |
| `chain-replay.json` | 实测回放，前六个环节不适用（C-11） | 采样率与中心频率取自清单、四态如实传出 |
| `chain-mixed.json` | 混合增强，80 MS/s 短窗（C-11） | 合成目标走全链、实测背景在 S4 相加；配套场景 `scenarios/mixed-wideband.scenario.json` |

再生成（改了槽位表或编译规则之后；经真实的 parseChain → compile 路径，参数一件不丢，2026-09-14 起 `_gen.ts` 带模式参数）：

```
cd web && npx tsx src/chain/examples/_gen.ts 3x3-aoa  > ../tests/regression/diagrams/chain-3x3-aoa.json
cd web && npx tsx src/chain/examples/_gen.ts 3x3-tdoa > ../tests/regression/diagrams/chain-3x3-tdoa.json
```

跑法（场景必须一并给，框图里只写 `scenario_id`，路径是内部参数，D-037）：

```
./engine/build/cuav_run --validate tests/regression/diagrams/chain-3x3-aoa.json \
  --scenario data/scene/beijing-yayuncun/scenarios/demo-03.scenario.json \
  --library-root models/recognition
```

**它们与 `slice6-smoke` 的分工**：端到端那套从浏览器出发，验的是「用户点得出这个形状」；
这两份从命令行出发，验的是「这个形状的文件引擎还认」。前者慢、覆盖界面，后者快、可在
改格式时随手跑一遍。

## 五、跨层一致性算例 ① 的典型链路实例（C-5，2026-09-14，D-067）

`crosslayer_pd_chain.py` + `scenarios/crosslayer-pd.scenario.json`。比对双方：M1/M2 侧是 D-026 选定的确定型目标检出率公式
（`algos/reference/energy_detector.py` 的 `pd_deterministic_signal`），输入是链路预算给出的带内信噪比（路损取 `links.jsonl` 的实际值）；
M3 侧是**用户在框图页会点出来的那条典型链路**（缺省链路换场景、40 s、ADC 16 bit、加评价器）跑出的 `metrics.json` 帧级 Pd。

场景参数在跑之前按解析预测冻结（推导在场景文件的 `trace.notes`），看到结果后不回头调：站点即 demo-01 的 site-1，源定点正东 2.9 km、
高 50 m、无航线无开关事件，`burst` 周期 0.512 s（250 帧）、导通 0.2（50 帧，边沿在帧边界），`tx_power −16 dBm` 使带内信噪比约 −9 dB。
**为什么用突发不用连续单音**：连续信号从 t = 0 起会被滑动删截的环吸收（C-3 已知行为），Pd ≈ 0.7 时 30% 的漏检帧持续进环、
估计上漂，与「噪声已知」的解析式不可比；突发的 80% 关断期让环保持干净。

首跑结果（macOS，原型阶段验证值）：路损 109.457 dB，带内信噪比 −8.99 dB，M = 921 bin，η = 1.104928；解析确定型 Pd **0.7164**
（随机型 0.7151）；蒙特卡洛 19531 帧、真值帧 3931，Pd **0.7026**，Pfa 0.00147（目标 0.001）；**差 0.0138**，方向为偏低——
漏检的导通帧进了噪声环，估计略偏高。突发级：79 段真值检出 78，虚警段 22，发现时延均值 1.1 ms。识别准确率 0.53 只作信息：
−9 dB 带内信噪比下特征本来就差，不是本算例的判据。`evaluate.py` 对拍逐值一致。

跑法：`uv run --quiet --with numpy python tests/regression/crosslayer_pd_chain.py`（已接进 `scripts/build-all.sh`；
超差退出码 1 并打印两侧数字与候选原因——按铁律 10 记为发现、查根因，不调参）。
