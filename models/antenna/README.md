# 模型卡：天线增益 `AntennaGain`

**组件**：`AntennaGain`，实现在 `engine/src/antenna.cpp`，声明在 `engine/include/cuav/components/antenna.h`。
**分级**：M3 施加 / E1 快速估算级 / V2。**依据**：04 §7.4（接收天线模型）、附录 A（天线首期必做
「全向、简化方向图、极化和馈线损耗」）；概念模型 EM-B-07 §10.1（链路预算中的方向增益与极化损耗）、
§10.3（典型方向图抽象的 E1 档）、§15（精度等级表）；决策 D-051、D-050 问题 ①。
**落地**：2026-09-07，C-2。

---

## 1. 这个模型算什么

给复基带样点乘一个实数增益，增益由方向图、指向、极化与馈线损耗四项合成：

```
G_dB = 方向增益(Δaz, Δel) − 极化失配损耗 − 馈线损耗
```

其中方向偏差 `Δ = 来波(或去波)方向 − 视轴方向`。样点乘 `10^(G_dB/20)`，不改变流长度。

**不算什么**：不算路损（信道组件的事）、不算发射功率（辐射源的事）、不算噪声（前端的事）。
这三项此前折在 `SceneBoundChannel` 一处（切片 ②），C-2 把它们拆开，两种口径给出的接收电平
逐值相同（对拍见 `engine/tests/test_channel.cpp` 的「增益口径等价」）。

## 2. 方向图：为什么是解析式

D-050 问题 ① 的拍板结论是**解析式，不用查表**。两条理由：

1. 框图参数只允许四种标量（`docs/diagram-format.md` §3），查表方向图必须走「版本号引用外部
   文件」那条路（同 `fir_version`）；
2. 首期没有任何实测方向图可填。写一个查表接口再喂进去编的数，比写解析式更不诚实。

采用 EM-B-07 §10.3 表中「定向天线 / E1 抽象」那一档：主瓣内按抛物线衰减，主瓣外截止于副瓣底。

| `pattern` | 公式 |
|---|---|
| `omni` | `G = gain_dBi` |
| `directional` | `G = gain_dBi − min( 12·[(Δaz/θaz)² + (Δel/θel)²], sidelobe_dB )` |

`12·(Δ/θ)²` 在 `Δ = θ/2` 处恰为 3 dB，这正是半功率波束宽度 θ 的定义，所以该式与参数表自洽。
方位差按 (−180°, 180°] 归约。

**查表方向图（EM-B-07 的 E2 档）随 P3**，届时新增 `pattern_version` 参数引用外部方向图文件，
本组件的其余部分不动。

## 3. 极化失配：五档标称表

`L_pol` 只在 `role = rx` 端计一次——两端各计一次会重复计入。取值按下表，来源标 **assumed**
（工程标称值，非实测）：

| 两端极化关系 | 损耗 | 依据 |
|---|---|---|
| 完全相同 | 0 dB | — |
| 线极化正交（垂直 ↔ 水平） | 20 dB | 理论上无穷大，工程上取标称隔离度 |
| 线极化与 slant45 之间 | 3 dB | `−10·log10(cos²45°)` = 3.01 dB |
| 线极化 ↔ 圆极化 | 3 dB | 理论值 `−10·log10(1/2)` = 3.01 dB |
| 圆极化旋向相反 | 20 dB | 同正交线极化 |

`peer_polarization`（对端极化）由典型链路视图从场景 `emission.polarization` 带出，与
`gain_dBi` 从场景带出是同一件事。因此本组件**不读场景文件**、不是 `scene_bindable` 组件。

## 4. 方向从哪来

`scene` 是**可选输入口**（`PortSpec.optional`，D-051）：

| 情形 | 方向来源 |
|---|---|
| 接了 `scene` 口 | 参数帧的 `aod_az_deg / aod_el_deg`（`role = tx`）或 `aoa_az_deg / aoa_el_deg`（`role = rx`），逐样点查帧、帧内零阶保持，与信道的增益施加同一口径（08 报告 §9.5） |
| 未接 | `aspect_az_deg / aspect_el_deg` 两个常量参数，并在 `status().notes` 记一条说明 |

未接不是「拿默认值顶替缺失值」（铁律 15）：没有场景时来波方向本来就只能由用户声明，
这是组件声明过的能力。定参链路（`FreeSpaceChannel`）与无场景的标准算例走这一路。

`pointing = heading` 时视轴方位跟随参数帧的 `tx_heading_deg`（平台航向），只对 `role = tx` 有意义。

## 5. 参数与取值来源

| 参数 | 单位 | 缺省 | 来源 |
|---|---|---|---|
| `role` | — | 必填 | 由典型链路视图按槽位填 |
| `pattern` | — | `omni` | 场景 `sites[].antenna.pattern` 首期只有 `omni` |
| `gain_dBi` | dBi | 必填 | 场景 `emission.antenna_gain_dBi`（tx）或 `sites[].antenna.gain_dBi`（rx） |
| `beamwidth_az_deg` / `beamwidth_el_deg` | deg | 60 | assumed，无实测依据 |
| `sidelobe_dB` | dB | 20 | assumed |
| `pointing` / `boresight_*` | — / deg | `fixed` / 0 | 用户设置 |
| `polarization` / `peer_polarization` | — | `vertical` | 场景 `emission.polarization`；缺省是 assumed |
| `feeder_loss_dB` | dB | 0 | 用户设置 |
| `aspect_az_deg` / `aspect_el_deg` | deg | 0 | 用户设置，仅在 `scene` 口未接时生效 |

**全部缺省值都是 assumed，不是实测**。甲方给出实际天线参数后按 04 §11.3 标定并升版本。

## 6. 验证

`engine/tests/test_receiver_chain.cpp` 与 `test_channel.cpp`：

- 全向增益与方向无关；馈线损耗只在 rx 端计一次；
- 定向方向图三个解析锚点：视轴上等于峰值、`Δ = θ/2` 处恰好 3 dB、`Δaz = 90°`（θ = 60°）时
  `12·1.5² = 27 dB` 被副瓣底 20 dB 截住；方位差 +350° 与 −10° 等价；
- 极化五档表九种组合，且 tx 端恒为 0；
- `scene` 口接与不接的两条路径各自正确，且接了口就不再记「未接」的说明；
- `pointing = heading` 时视轴跟随航向；
- **口径等价**：在 `demo-01` 上，「辐射源按 tx_power 出电平 + tx 天线 + 纯路损信道 + rx 天线」
  与切片 ② 的「单位功率辐射源 + 折在一处的链路预算信道」给出同一接收电平（差 < 0.001 dB，
  验收线是 0.05 dB）。

## 7. 适用范围与不适用

**适用**：单站单链路、各向同性或单主瓣定向天线、慢变几何（10–100 Hz 帧）下的链路电平演示与
检测识别试验。

**不适用**：阵列测向（需要阵列流形与通道幅相误差）、平台遮挡与机体散射、互耦、频率相关方向图、
扫描天线的驻留时序。这些是 04 §7.4 明确列为「首期不要求」的项，随 P3 与后置能力包 P1/P2。

方向图是 E1 抽象，**不得用于方向图形状本身的定量结论**（如副瓣电平的验收）；它的用途是让
链路电平随几何变化时有一个合理、可解释、可复现的方向依赖。
