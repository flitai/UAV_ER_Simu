# 模型卡：数字下变频 `DDC`

| 项 | 值 |
|---|---|
| 组件类型 | `DDC` |
| 环节 | 数字下变频（04 §7.7；S3 → S4） |
| M / E / V | M3 / E2 / V2 |
| `model_id` | `EM-B-11`（接收机基础，与 `ReceiverFrontEnd` / `AdcQuantizer` 同一概念模型） |
| 实现 | 手写 C++：`engine/src/ddc.cpp`（封装）+ `engine/src/dsp.cpp` 的 `ddc_*` 三件（算法核） |
| 系数表 | `models/adc-ddc/fir_lp_v1.json`（真理源）→ `engine/src/ddc_taps.cpp`（生成物） |
| 步骤 / 决策 | 06 §9D M-2；D-070（修订 D-036） |

## 1. 做什么

04 §7.7 的五步，逐条落在代码里：

1. **数控振荡产生复本振** —— 相位累加器，单位是**圈**不是弧度（见 §4 契约 ①）；
2. **复混频搬移** —— 乘 `exp(−j2π·f_shift·t)`，输出中心频率 = 输入中心 + `f_shift_Hz`；
3. **低通保留目标带宽** —— 等波纹 FIR，通带 `0.4·fs_out`、阻带 `0.5·fs_out` ≥ 60 dB；
4. **按整数比抽取** —— `fs_out = fs_in / decim`；
5. **更新元数据** —— 采样率、中心频率、样点序号、溯源（见 §3）。

## 2. 参数

| 名 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `f_shift_Hz` | number | 0 | 频移。典型链路由频率计划填 `f_tx − f_rx`，把目标搬到 S4 零频附近 |
| `decim` | number | 1 | 整数抽取比，取值须在冻结表内（见 §5） |
| `fir_version` | enum | `lp_v1` | 抗混叠抽头版本 |

`decim` 有意保持 number 而不是枚举下拉：前端 `plan.ts` 一路用 `num()` 读它，改成字符串枚举会牵动
频率计划的取值链路。取值不在表里由 `configure()` 明确报错并列出支持的取值，不静默顶替（铁律 15）。

## 3. 时间锚：输出样点 m ↔ 输入样点 m·D

08 报告 §8 口径一与口径二的落地方式：封装层把抽取相位的初值置为群时延 `gd`，于是第一个输出取在
绝对输入样点 `gd`，其对称窗口覆盖输入 `[−gd, +gd]` —— 等价于「在输入时刻 0 处施加的零相位滤波」。
`start_sample_out` 因此**自 0 起、严格连续**。

这条口径不是唯一可能的选择，但它是唯一能让下游不改一行的选择：

- `FeatureExtractor` 断言 `start_sample == frame_index · nfft`（`processing.cpp:971`）；
- `SceneBoundChannel` / `FeatureExtractor` 要求块的 `start_sample` 严格连续（`channel.cpp:193`）；
- S4 产品索引的 `t0_s = first_sample / fs` 仍是 0，前端 `timelineOps.ts:26` 的「没有索引按 0」兜底不被打破。

**对 08 §8 口径一的一处修正**：口径一写成**逐块**等式 `start_sample_out = (start_sample_in − gd)/D`
时，只在 `D | (start_sample_in − gd)` 才成立，而输入块边界一般不满足。正确的实现是封装层自己数输出
样点数，**逐样点关系恒成立、逐块关系是它的推论**。

**输出样点数的闭式**（进单测）：`out_count = (n_in > gd) ? (n_in − 1 − gd)/D + 1 : 0`。
实测 demo-02：60000000 入 → 29999973 出，与闭式逐位相符。

## 4. 两条契约

C++ / Python 参考必须逐字同序（铁律 10）：

① **NCO 相位以圈计**。`2π` 不是精确可表示的二进制数，`phase -= 2π` 每次回卷注入一次舍入
（`ReceiverFrontEnd` 就是这么写的，那里可以接受）；而 `[1,2)` 区间减 `1.0` 指数不变、尾数对齐，
**结果精确**。于是相位序列只是「已处理输入样点数」的函数：与块长无关、逐位复现、跨语言逐位相同。
唯一的分歧落在 `cos/sin` 的末位（各家 libm 不是正确舍入）。

② **FIR 点积按抽头升序累加**。Python 参考因此不用 `numpy.dot` / `sum`——成对求和与顺序累加在
最后几位上不同（D-046 ⑧ 踩过同一个坑）。

**实测结果比契约承诺的还强**：四个算例（D = 1 / 2 / 4 / 20）与 Python 参考的最坏相对差是 **0**，
即 float32 输出**逐位相同**，没有落到 1e-6 的容差上。

## 5. 系数表

等波纹（Parks-McClellan）设计，`scripts/design_ddc_fir.py`（`scipy.signal.remez`）。
通带 `0.4·fs_out`、阻带 `0.5·fs_out` ≥ 60 dB、通带纹波 ≤ 0.2 dB、**奇数抽头**使群时延 `(N−1)/2`
为整数个输入样点（08 §8 口径二，首期不引入分数延迟器）。通带增益归一 `sum(h) = 1`。

| D | 抽头 N | 群时延（输入样点） | 阻带 | 通带纹波 |
|---|---|---|---|---|
| 1 | 1 | 0 | —（纯频移，不滤波） | 0 |
| 2 | 55 | 27 | 62.01 dB | 0.1381 dB |
| 4 | 111 | 55 | 62.42 dB | 0.1301 dB |
| 5 | 137 | 68 | 61.96 dB | 0.1399 dB |
| 8 | 219 | 109 | 62.02 dB | 0.1382 dB |
| 10 | 273 | 136 | 61.88 dB | 0.1408 dB |
| 16 | 437 | 218 | 61.98 dB | 0.1387 dB |
| 20 | 547 | 273 | 62.13 dB | 0.1366 dB |

抽头数 ≈ 27·D；**每个输入样点的乘加数恒为 ≈ 27，与 D 无关**（抽取型 FIR 只算要用的输出）。
只存半表（含中心抽头），装载时镜像展开——等波纹设计的输出不保证**逐位**对称，存全表会让三方的
群时延在 1e-17 级上对不齐。

**取值来源**：全部 `derived`（由设计脚本按上述指标算出），不是假定值也不是实测值。
**独立校验**：`matlab/design/check_ddc_fir.m` 用 Signal Toolbox 的 `firpm` 重设计一遍，
实测两家吻合到 **1.5e-14**。

## 6. 铁律 4 的分工

| 检查 | 在哪 | 为什么 |
|---|---|---|
| `fs_in % decim == 0` | 引擎 `process()` 首块 + 前端 `plan.ts` 的 `decim` | 两侧同式（`fmod`），口径写在一处 |
| `\|f_shift\| + fs_out/2 ≤ fs_in/2` | 引擎 `process()` 首块 | 保留的窄带窗口必须整块落在输入奈奎斯特窗内，否则输出带是从输入带边缘折回来的镜像 |
| `\|Δf\| + B/2 + 保护带 < Fs/2` | 前端 `plan.ts` 的 `edge` | 要发射带宽与跳频序列，组件拿不到 |
| 过渡带 `\|Δf − f_shift\| + B/2 ≤ 0.4·fs_s4` | 前端 `plan.ts` 的 `transition` | 同上 |
| 抗混叠本身 | 不检查 | 由 `lp_v1` 的阻带指标**构造性保证** |

**`decim = 1` 不做奈奎斯特那道闸**：不抽取就没有混叠可言，此时 DDC 退化成纯频移，谱整体**循环**
旋转、越过奈奎斯特的内容绕回另一端——这正是数字混频器的固有行为，不是错误。拿同一条判据去卡它
会让「只改中心频率」这件事永远做不成（任何非零频移都过不去）。

## 7. 解析锚点（`engine/tests/test_ddc.cpp`）

- 通带单音搬到零频，幅度差 **< 0.05 dB**，搬移后每样点相位增量 < 1e-3 rad；
- 阻带单音抑制 **≥ 60 dB**（实测 **91.1 dB**，D = 2、4 MHz @ 10 MS/s）；
- `fs_out = fs_in/D`，输出样点数合闭式；
- 冲激在输入 `n0` → 输出峰值在 `m = n0/D`，偏差 **0 样点**（D = 1 / 2 / 4 / 5）；
- 块长 1 / 7 / 997 / 整块的结果**逐位相同**；`reset()` 后重跑逐位相同（铁律 9）。

## 8. 已知边界

1. **收尾丢尾不补零**。滤波器延迟线里剩的真实样点不再吐出（末尾至多 `gd/D` 个输出样点）。
   补零冲出来的那几个输出是用**根本没采到的数据**算的（铁律 15），而且会在 S4 谱的末几行留下
   一段淡出、下游可能读成一次真实的电平变化。与 `EnergyDetector` 丢不满一帧、`FeatureExtractor`
   丢未收口段同一口径。**首端不对称**：起始 `⌈gd/D⌉` 个输出样点含滤波器启动瞬态（零前史），
   这是「`start_sample` 自 0 起」的代价，无法避免；末端没有理由去编造，所以不对称是有意的。
2. **真值边界的取整落差**。源端按站点的宽带 `fs` 建活动时间线，评价器按检测行的窄带 `fs` 重建，
   两边都四舍五入。单个边界至多差 `(D+1)/(2·fs_w)`——实测 **100 / 200 / 700 ns**（D = 2 / 4 / 20），
   相对一个检测帧（205 / 410 / 2048 µs）可忽略。**但跳频边界的落差随跳数累积**（边界是
   `start_n + k·dwell_n`，`dwell_n` 的取整误差乘 k）：实测 D = 20、`dwell` 12.3456 ms 时每跳
   400 ns，8 跳后 2500 ns，已超过一个窄带样点。要累积满一个检测帧需 **1365 / 1638 / 1950 跳**。
   demo-02 的 10 ms `dwell` 在 5 MS/s 下整除，本期夹具的落差**恒为零**。评价器在两个速率不同时
   写一条 `status_.notes` 说明，不标降级——这是多速率下「源与真值逐位同源」（D-069）退化成
   「亚样点同源」的真实边界。
3. **混合增强模式 + DDC**：`compile.ts` 把 `mix` 排在 DDC 之后，而 `AddMixer` 要求两路采样率与
   中心频率一致。于是混合模式下开 DDC 要求回放背景的 `fs` 与中心频率**正好等于** DDC 的输出。
   10 报告 §2.4 设计过「由回放清单反推 `decim` 与 `f_shift`」，本期不做；本期只保证报错清楚不静默。
4. **单级抽取**。`decim` 受表限制（最大 20）。更大的抽取比应走多级（CIC / 半带级联），随 M-3。
5. **NCO 每输入样点一对 `cos/sin`**，是本组件的主要开销，本期不优化（查表 / 递推留性能评估）。
6. **缺省旁路**。`ddc` 槽位 `defaultBypass: true`：组件已落地，但接进缺省链会改变 demo-01 的产品、
   检测与评价基准，而 demo-01 是 500 kS/s、`decim` 只能取 1，抽取本来也无从谈起。缺省接线留 C-10。

## 9. 演示夹具

`tests/regression/diagrams/chain-demo-02-ddc.json`：demo-02 宽带场景，10 MS/s @ 2441 MHz，
`f_shift_Hz = −2.5e6`、`decim = 2` → S4 **5 MS/s @ 2438.5 MHz**，S3 与 S4 两个观测点并排看。

选 `decim = 2` 而不是 4：`decim = 4` 时通带边 `0.4·fs_out = 1.0 MHz` **恰好等于**图传的半带宽，
过渡带检查靠等号通过、一点余量不留。

实测（macOS，原型阶段验证值）：六秒双源，60000000 入 → 29999973 出，墙钟 15.7 s（实时因子 0.38）。
S4 谱上（t ≥ 5 s 两源同时发射）：图传中心 **−74.93 dBm**、带边 +0.95 MHz **−77.11 dBm**；
五个跳频点相对 S4 中心落在 +1.625 … +4.9375 MHz，其中 **+1.625 MHz 那一跳还在通带里、读 −93.75 dBm**
（底噪 −147 dBm），另四个进了阻带被压掉——「DDC 选出了图传频段」在瀑布上直接看得见。
`metrics.json` 与 `algos/reference/evaluate.py` **逐值一致**，Pd 1.0、识别准确率 1.0。
