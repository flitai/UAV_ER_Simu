## 1. 波形

按场景 `emission.waveform` 生成三种，**都归一化到「发射期间」的单位功率（0 dBm）**，
绝对电平由施加类信道按链路预算给出（D-045）：

| type | 生成方式 | 归一化口径 |
|---|---|---|
| `tone` | 复指数，频偏 `center_Hz + offset_Hz − 观测中心` | 恒为 1 |
| `noise` | 复高斯 → 4 阶巴特沃斯带限 → 频率搬移（见 §3） | `E|x|² = 1` |
| `burst` | 门控的复指数，门控按**绝对样点号取模**：`idx % period_n < on_n` | 导通区间内为 1，断开区间**精确为零** |
| `ofdm` / `droneid` | 按机型预设逐突发生成（§7） | 突发内在期望上为 1（按子载波频点的 \|H\|² 均值补偿），突发之外**精确为零** |

`period_n = round(period_s · fs)`、`on_n = round(duty · period_n)`；折不出有效整数图案即报错，
不把占空比夹到端点（铁律 15）。

**已知口径（容易读错）**：`burst` 的全程平均功率是 `duty × 1 mW`，瀑布上的时间平均电平
比链路预算低 `10·log10(1/duty)`，**突发峰值才等于链路预算**。

## 2. 活动时间线按样点施加（G-6）

`tx_on` / `tx_off` / `hop` 的边界折到**绝对样点号**上（`geo::sample_at` 四舍五入，全仓唯一口径），
`process()` 把每块切成若干「同频同开关」的子段逐段推进。

- **与块长无关**：子段边界来自时间表而不是块边界，加法的项与次序都只是样点号的函数，
  于是换块长逐位相同（铁律 9，`test_channel.cpp` 五种块长对拍）。
- **相位累加器跨子段不重置** —— 这是 **DDS 型的相位连续跳频**。非相干跳频（每跳随机相位）
  是另一种建模，本期不做。
- `sequence + dwell_s` 按 `k = (n − start_n) / dwell_n`、`seq[k % len]` 纯整数循环。
- **三条闸一律报错、不静默夹**（铁律 15）：停留折出 0 个样点、两个状态相反的开关折到同一样点、
  两条跳频活动折到同一样点。取整落差超过 0.1% 只推一条 note。
- `takeoff / cruise / hover / land` **在物理上零作用**，只作状态标签与显示
  （`docs/scenario-format.md` §6 的既有语义；航线本身已含悬停）。

**C-8 之前是按块起点取值的**，块长缺省 65536 样点 = 500 kS/s 下 131 ms、10 MS/s 下 6.55 ms。
`demo-01` 记录在案的「发现时延 14.7 ms、`fn = 7`」正是它造成的，改完之后收到 0（D-069 step 3）。

## 3. noise 的带限与频率搬移

截止 `fc = emission.bw_Hz / 2`（复基带占 `[−fc, +fc]`，总占用带宽正好 `bw_Hz`），
4 阶巴特沃斯低通 = 两节双二阶级联，双线性变换加频率预畸变，转置直接 II 型，**状态跨块保持**。
单位功率靠冲激响应的 `Σ|h|²` 归一（判据「连续 16 个样点 `h² ≤ 1e-20·acc`」，上限 2²²）；
`init()` 里先推 `n_settle` 个样点丢掉，否则「发射期间平均功率恰为 1 mW」这句合同在开头
几百个样点上不成立。**不带任何用户参数，一切从场景的 `bw_Hz` 派生。**

**适用范围与已知界限**：

- **阻带不是砖墙**。99% 占用带宽比 `−3 dB` 带宽宽：实测 1 MS/s / `bw 200 kHz` 时是 **276 kHz**。
  要更陡的边沿得换更高阶或 FIR，属 C-10（M-2 / M-3 的 Coder 产物）。
- 数字域因预畸变比模拟域陡：`fs 10 MHz / fc 1 MHz` 时 `2fc` 处是 **−27.97 dB** 而不是 −24 dB。
- **搬移在离散域是循环旋转**：离中心比 `Fs/2` 更远的那半边裙边会绕到带的另一头。
  判据取**绕折功率的积分占比**（4096 格中点法），超过 `1e-3` 才标降级 ——
  只看带边那一点的衰减会把物理上没问题的配置误判成降级（实测带边 39 dB 抑制对应的
  绕折功率只有 **2.4e-5**）。
- `bw_Hz` 不小于采样带宽时**不带限**、输出全带白噪声并标降级。
- `offset_Hz` 自 C-8 起对三种波形通用。此前 noise 既不带限也不搬移，写了 `center_Hz`
  与 `offset_Hz` 都**不起作用**（谱质心恒为 0）。

## 4. 铁律 4 的闸

`|Δf| + B/2 < Fs/2` 对**基频与每一个跳频点**逐个校验，三处同一口径
（`geo::emitter_center_set`）：`Scenario::cross_check`、`SceneEmitterSource::configure`、
前端 `web/src/chain/plan.ts` 的 `edge` 与 `transition`。跳频点越界时报文带出处
（哪条活动的哪一项）与「把 `fs_Hz` 提到大于 N Hz」这个算得出来的建议。

## 5. `golden-02` 上的实测（原型阶段验证值，D-028）

场景 `data/scene/beijing-yayuncun/scenarios/golden-02.scenario.json`，
链路 `tests/regression/diagrams/chain-golden-02.json`，6 s、10 MS/s、单站两源，
墙钟 **12 s**（macOS，实时因子 0.5）。

| 项 | 实测 |
|---|---|
| 帧级 | Pd **1.0**、Pfa **0.0073**、F1 0.9973 |
| 突发级 | 真值 252 段，匹配 **252**，虚警段 30 |
| 识别 | 评价 152 段，准确率 **1.0**；`rc_hopping` 180 行、`video_link` 2 行 |
| ADC | 削波 **0** 个样点（前端增益 20 dB、满量程 −20 dBm） |
| 观测点 | S4 谱 58593 行、包络 14649 行，状态 `valid` |

**`rc_hopping` 至此第一次由真实链路走通** —— C-4 留的那笔验收（06 §9G C-4 行、
`models/recognition/README.md` §4）到此销项。

### 5.1 三条必须照实说的边界

1. **重叠段里单频段能量检测分不开两个源。** `golden-02` 的 5–6 s 两者同时发，
   检测器把整段并成**一个**突发（实测段号 181，跨 `[5.0, 6.0]`），100 个跳频突发被吞掉。
   这不是缺陷，是每站只有一个单频段能量检测器的必然结果，场景有意留出这一段来展示它。
   子带 CFAR 与多检测器属 P3。
2. **「突发级 252/252 全匹配」与「识别准确率 1.0」说的不是同一件事。** 前者是因为那一个
   合并段与每个跳频突发都完全重叠（`overlap / min(len) = 1`）；后者的分母只含**产出了识别行
   并匹配上真值的段**，重叠段里的 100 个跳频突发没有各自的标签。准确率 1.0 的含义是
   「产出的每一行识别都对」，不是「把它们都分开了」。
3. **第一个跳频突发能判对是场景顺序带来的。** `TemplateClassifier` 的 `hop_from_prev_Hz`
   权重最高而第一个突发没有「上一段」（`models/recognition/README.md` §4）；`golden-02` 里
   图传先发，于是跳频的第一个突发拿图传那一段当「上一段」，频率差照样够大。
   换一个跳频先发的场景，第一段仍会落 `unknown_ambiguous`。

### 5.2 检测器在这个场景上的已知行为

`det` 报了「噪声估计陈旧 28785 帧」：滑动估计只纳入**未命中帧**，图传连发的两秒里没有
未命中帧可纳入，估计就停在最近一次更新（D-063 的已知行为，不是缺陷）。整体 Pfa 0.0073
高于 1e-3 的目标，与 D-063 记的「环境代价」同源：靠识别与子带 CFAR 解决，不靠抬门限。

## 6. 不做

非相干跳频、`gfsk` / `fhss` 波形（Q-3）、辐射源模板 `TemplateSource`（T 线，D-045）、
带限用 FIR 或更高阶（C-10）、`takeoff / cruise / hover / land` 的物理效应、
跳频源接进多站测向定位（`engine/src/locate.cpp` 的同频配对取自 20–100 Hz 的参数帧，
对毫秒级跳频是混叠抽样；`golden-02` 是单站，本期碰不到，**记为已知限制**）。

## 7. OFDM 族：DJI 图传、DJI 遥控上行、DroneID（Q-2，D-088）

### 7.1 结构从哪来

**机型预设表** `models/radiator/presets-v1.json`（每项带 V / P / S / A / D / M 出处与引文，这里不重抄）：

| 预设 | 数值结构 | 子载波 | 突发 | 帧排布 | 可信度 |
|---|---|---|---|---|---|
| `dji-video-10m` | 1024 点 / 15.36 MS/s | ±300 | 15 或 30 符号（1.071 / 2.141 ms） | 2 ms 时隙按概率抽（借 A/D/F/G 族） | V1 |
| `dji-video-20m-a` | 2048 / 30.72 | ±600（18.015 MHz） | 同上 | 2 ms 时隙，占空 0.411、长突发占比 0.2033 | V1 |
| `dji-video-20m-c` | 2048 / 30.72 | ±600 | 13 或 15 符号（0.928 / 1.071 ms） | 4 ms 时隙，占空 0.2181 | V1 |
| `dji-video-40m` | 4096 / 61.44 | ±1200（36.015 MHz） | 15 或 30 符号 | 2 ms 时隙，Mavic 3 5.8 GHz 的占空与占比 | V1 |
| `dji-uplink-1m/2m/4m` | 1024 / 15.36 | ±37 / ±74 / ±147 | 7 符号 = 0.500 ms（4m 档拉长 CP 到 0.548 ms） | 图案 [发, 空, 发, 空, 空] × 2 ms，「发」以 q 空过 | V1 |

载荷是种子随机比特、不编码，**不含任何真实身份**。

### 7.2 生成路径

1. **帧排布**（`geo::FrameSchedule`）：时隙与突发全在**整数原生样点**上；图传每时隙按概率抽「空 / 短 / 长」，
   抽签是 `splitmix64(场景 seed, 辐射源 id, 时隙号)` 的计数器哈希——不耗随机流，评价器各算一遍同一张表。
   上一个突发没结束（再加 64 个原生样点）之前开始的时隙一律空。
2. **原生率调制**（`ofdm::Modulator`）：逐符号放数据或 ZC，IFFT（`dsp::FftPlan`，与 `fft_inplace(double)` 逐位同）
   加 CP；`x[n] = g·Σ X_k·e^{+j2πkn/N}`，`g = 1/√(2K)`。载荷种子 = `mix64(key ^ mix64(时隙号))`，
   `key` 是 `init()` 从私有子流取的一个数——**共享随机流一个数也不多取**。
3. **有理重采样**（`RationalResampler`，Coder 核）：L = 125、M ∈ {24, 48, 96}，原型低通 2501 抽头
   （`models/radiator/fir_rsmp_v1.json`，Kaiser 窗，通带 0.2935·fs_n、阻带 0.5·fs_n 处 64.90 dB、纹波 0.0072 dB）；
   时间锚「站点样点 m ↔ 原型序号 m·M + gd」，即站点样点 m 恰在原生时刻 m·M/L。只升采样：
   15.36 MS/s 的预设取 20 / 40 / 80 MS/s，30.72 取 40 / 80，61.44 取 80。
4. **整突发开关**：突发起点（连续时间）发射机开着，整个突发发完；关着，一个样点都不发。**不在突发中间硬切**。
5. **按突发定频点**：突发中点时刻的中心频率（跳频的 hop 活动照旧写），整个突发连同滤波拖尾用它；
   支撑之外恰为 +0，相位累加器照旧逐样点推进。
6. **单位功率**：按带能量的子载波数归一，再补滤波器在各子载波频点的 `|H/L|²` 均值 c（10 MHz 档 c = 1.000308）。

### 7.5 已知边界

- **越过带边的残余**：场景载入只按占用带宽查铁律 4（`|Δf| + B/2 < Fs/2`）。规划时加过「按重采样阻带边 0.5·fs_n」
  的第二道闸，写夹具时撤掉：它会拒掉实测里就有的配置（C/E 族 2457.5–2475.5 MHz、上行 2402–2477 MHz 的跳频跨度，
  都是 DroneRFb 在 80 MS/s @ 2440 MHz 下录到的）。代价是贴带边时，符号旁瓣经滤波过渡带衰减后的残余会绕折到带的另一头。
- **一源一标签**：DroneID 与图传写成两个辐射源（同航线），地图上图标叠放；遥控器写成辐射源时机型图标仍是无人机。
- **上行 0.39 ms 那一峰**（C/E 族，27–29%）未建模；4.4 MHz 档的 0.548 ms 靠拉长 CP 凑，CP 长度是假定。
- **跳频序列在编辑器里不自动生成**：`algos/reference/ofdm_ref.py --uplink-sequence` 生成、手写进 hop 活动；
  跳步在栅格上均匀抽，不拟合实测的 2 / 3 / 5 MHz 倍数分布（A 档）。
- **星座不混合**、**不做信道编码**、**不做加窗 / WOLA**（带外裙边由重采样滤波器的过渡带决定）。
- 采样率只有表里那几档；其余站点采样率在场景载入时即拒并列出可取值。
