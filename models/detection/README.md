## 1. 算什么

对复基带 x[n]（引擎内部 |x|² = mW，D-047），按帧长 `nfft` 切帧、**不加窗、不重叠**，每帧 DFT：

```
P_k        = |X_k|²                                  逐频点功率（fftshift 后的 k）
T          = Σ_{k∈B} P_k                            频段 B 内能量（M = |B| 个频点）
N̂_k        = median_frames(P_k) / ln 2               逐频点噪声估计：帧维中位数按指数分布修正
Λ          = T / Σ_{k∈B} N̂_k                         归一化检测量，H0 下均值 1
η          = 解 Q(M, M·η) = pfa                     门限只依赖 M 与 pfa（正则化上不完全伽马）
hit        = Λ > η
```

不加窗是刻意的：汉宁窗让相邻频点相关，H0 的卡方自由度不再是 2M，解析虚警率失效。
门限求解与 Python 参考同算法同分支（`dsp::threshold_for_pfa` / `threshold_for_pfa`），
黄金基准口径 1e-9。

## 2. 两种噪声估计（`noise_mode`）

| 模式 | 估计 | 何时用 |
|---|---|---|
| `probe`（缺省） | 前 `noise_frames` 帧攒一次逐频点中位数后**固定**；探针帧本身在攒够后一次补判 | 手写框图、黄金基准 `energy_detector.json`（切片 ①，一字不改） |
| `sliding` | 最近 W = `noise_window_frames` 帧的环，**只纳入未命中帧**（删截），环变了才重算；门限不变 | 典型链路模板固定（D-026） |

滑动模式逐帧顺序（C++ `judge_sliding()` 与 Python `sliding_from_power()` 同序，
黄金基准 `energy_detector_sliding.json` 4000 帧逐帧对拍，statistic 相对误差实测 4.1e-7）：

```
① 环空 → 本帧先入环（第 0 帧的 Λ 因此恒为 ln 2，不会命中；noise_frames_used = 1）
② 环变过 → N̂ 只对频段内 bin 重算（有序副本插删 O(W)，中位数 O(1)）
③ 判决；noise_frames_used = 判决时的环大小；环连续超过 W 帧没更新 → 计一帧「陈旧」
④ 未命中且尚未入环 → 入环（满则弹最旧）；命中的帧**不入环**
```

暖机：环填满前用已有帧判决，不标降级（运行初期的正常状态），但头几帧的估计极不可靠
（M = 5 个 bin、1 帧中位数时虚警率远高于目标），单测与端到端都只对暖机之后断言。
环**从未**填满（整次运行短于 W 帧）→ `degraded` + note，与 probe「探针不足即降级」对称。

## 3. 突发分段与逐帧行

命中帧按 `merge_gap_frames` 并段：与上一命中帧之间的非命中帧数 ≤ 该值即同段，`segment_id` 从 0 起，
非命中帧为 −1（JSON `null`）。两种模式都分段。每帧经观察者 `on_detection` 上报一行
（`detections.jsonl`，字段见 `docs/display-products.md` §5.1），flush 时 `on_detection_summary`
一条摘要（`detections.index.json`，带溯源）。

dBm 读数（输入已标定且 `band_power_dBm = true`）：未归一化 DFT 的 Parseval `Σ_k |X_k|² = nfft · Σ_n |x_n|²`，
频段内每样点平均功率 `= T / nfft²`，故 `band_power_dBm = 10·log10(T / nfft²)`、
`noise_dBm = 10·log10(Σ N̂ / nfft²)`；`snr_dB = 10·log10 Λ` 即 (S+N)/N。
`overload` = 组成该帧的任一块 `clip_count > 0`（帧可跨块；削波是数据标记不是降级，D-051）。

## 4. 已知行为（不是缺陷，是中位数估计的边界）

1. **从 t = 0 起持续发射的信号被吸收**：第 0 帧无条件入环，此后每帧都不命中、都被纳入，
   估计从此含信号——与 probe 的「连续满带信号被中位数吸收」是同一件事。参考噪声必须有一段
   无信号窗口：示例场景 `demo-01` 的无人机 3 s 才 `tx_on`，端到端实测从 3.015 s 起持续检出
   1457 帧一段；`demo-03` 三机从 0 s 起持续发射，三站中两站零命中（真实后果，写在 slice6 里不断言命中）。
2. **删截只在参考干净时保持持续信号检出**：信号一来，命中帧不再入环，环冻结在此前的噪声上，
   估计不再更新（`noise_stale_frames` 计数、记 note、不降级）；背景若在信号期间漂移，参考跟不上。
3. **占空比 > 50% 的信号被当成噪声**：中位数在一半以上的帧含信号时落到信号电平。DS-6 复跑里
   繁忙频段（2410–2420 MHz）部分片的占用超过一半，逐片中位数最高到 4.49，两种口径都跟不上。
4. **起伏的强背景会把估计往下棘轮**：同频双音的拍频使功率在两个电平间摆动，只有低谷帧被纳入，
   估计落到谷底电平，之后多数帧命中。这是删截估计的固有副作用。
5. **全带统计量看不见比带内持续单音弱的突发**：Λ 是频段能量对频段噪声估计之比，持续单音被吸收后
   仍占据分母，比它低约 4 dB 以上的突发推不动 Λ。逐 bin / 子带 CFAR 随 C-4 与 P3。

## 5. DS-6 分半标定的复跑（2026-09-12，原型阶段验证值，D-028）

D-026 的实测：静态门限在一半真实背景上标定、换到另一半虚警率超目标 7.0–7.2 倍，随机打散分半则达标。
计划把「sliding 下比值回到 1」定为 C-3 的验收项，**实测没有回到 1**（`algos/reference/ds6_sliding_check.py`，
报告 `data/iq/measured/ds6-sliding-report.md`）：

| 频段 | 档 ② 分半标定（静态 → 滑动） | 逐片中位数散布（静态 → 滑动） | 50% 分位两半区（滑动） | 99.9% 分位两半区（滑动） |
|---|---|---|---|---|
| 2410–2420 MHz | 7.20 → 7.27 倍 | 6.60 → 6.44 dB | 1.118 / 1.092 | 3662 / 4321 |
| 2430–2440 MHz | 7.00 → 8.30 倍 | 1.32 → 0.52 dB | 1.042 / 1.051 | 77 / 101 |

读法：两半区在 50% 分位上对得上、在 99.9% 分位上对不上——**失配在尾部，尾部是真实的 WiFi / 蓝牙突发**，
两半文件采自不同时间与地点，突发的强弱与多寡本来就不同，任何噪声估计都归一不掉。滑动估计归一的是
分布的主体：安静频段逐片中位数散布 1.32 → 0.52 dB。这条改写了对 D-026 的解读（漂移在干扰尾部而非
噪声底），是 C-3 的一个发现，不调参使其通过（铁律 10）。

## 7a. 场景页的探测范围（覆盖场，D-079 / D-080）

场景页「图层 ▸ 探测范围」把本卡的判决搬到地图上：假设焦点目标挪到网格上每一格、按给定离地高度，
每个侦测站的检测器**单帧**检出概率是多少。**不跑 IQ**，是本卡 §1 解析式在链路预算上的直接代入，
**算在引擎**（`cuav_run --field`，经 `POST /api/v1/coverage`；D-080 起，D-079 那一版在浏览器里算）：

```
g   = link_geometry(站, 目标)（E3 才带建筑遮挡，与链路帧同一个地图、同一个平面帧）
b   = link_budget(g, f, nf, 框图的传播配置, 阴影样本 0, 极化)       （与链路帧同一个函数）
S   = P_tx + G_t + G_r − b.path_loss_dB
N   = −174 + nf + 10·log10(M · fs / nfft)                             （前端增益两边抵消）
η   = 解 Q(M, M·η) = pfa；Pd = Q(M, M·η / (1 + 10^((S−N)/10)))        （随机型，D-026 / D-068 ⑤）
开了统计阴影：Pd̄ = E_X[Pd(snr − X)]，X ~ N(0, σ)，σ 与链路帧同取视距那一档
合并 = 1 − Π(1 − Pd_i)
```

**界面上一律按 E3（自由空间 + 建筑遮挡）算，不随框图的传播档位变**（D-081，用户 2026-09-27：「作为可视化不做与
E1 和 E2 的对比」；此前 D-080 ④ 曾定为跟随框图）。引擎子命令本身接受任意传播配置（E1 / E2 的双径、城市经验、阴影、
天气），下面的阴影平均与读图事实表里的 E1 / E2 行是引擎能力的记录，界面不再用到。
参数：目标取焦点目标（发射参数由引擎从**已保存的**场景读）；`nfft / pfa / 频段` 取框图里绑到该站的检测器——
框图不属于当前场景时不用（各场景的站 id 重名），缺席时取组件目录缺省与 ±0.45·fs；
目标中心落在某站检测频段之外时，该站逐格 Pd = 虚警率并照实标「频段外」。

**阴影平均为什么是查表不是求积公式**：M ≈ 921 时 Pd 在 dB 轴上是一道一两 dB 宽的陡坎，σ = 6 dB 的高斯用
16 点 Gauss–Hermite 去积，节点比那道坎还宽——实测陡坡上一格（snr −11.05 dB）求积给 0.451、20 万次蒙特卡洛给
0.435，差 14 倍标准误（第一版单测挑的点 Pd 恒为 1、平均与否都是 1，没测出来；改成必须落在陡坡上才发现）。
改为先在 0.01 dB 细格上算 Pd、与离散高斯卷积成表、逐格插值：同一格 0.4346 对蒙特卡洛 0.4351。

**验证**：

  （72 个非视距）的逐点路损与链路帧 `path_loss_dB` **差 0**、视距判定逐时刻相同，网格文件两次运行逐字节相同；

**声明过的简化**（原型阶段验证值，D-028）：
1. 平地假设（铁律 2），站与目标都按离地高；地形不遮挡。
2. 建筑遮挡是**单刀口、取侵入最深的一栋**（D-074 ⑩ 第 3 条）。实测它会让损耗**随目标高度非单调**：

   侵入最深的那栋不一定是损耗最大的那栋。引擎的链路帧同样如此；改成「取损耗最大的一栋」是一次真正的
   遮挡基准变更（148 例），不在本步做。
3. 全向天线、无极化失配；单帧 Pd（不含多帧积累与滑动噪声估计的暖机）；跳频源按基频算。

## 9. 分子带检测（Q-4b，2026-10-05，D-093）

**要解决的事**：宽带（10–80 MS/s）里同时出现的几个信号——图传、遥控跳频、DroneID——被全带统计量并成一个突发。
golden-02 的帧级段号 181 一段盖住 5–6 s 的图传与 100 个跳频突发（D-069 ⑧）。分子带检测让它们各成各的段。

**落点**：在 `EnergyDetector` 里面，参数 `subband_bins`（最小块宽 K0，频点数）∈ {0, 2, 4, 8, 16, 32, 64}，0 = 关（缺省），
开了只能配 `noise_mode = sliding`。不走「信道化全部输出 → 每路一个检测器」：信道化是临界抽取、子带宽固定为 fs/M
（对 0.2 MHz 的 GFSK 太宽、一路图传横跨十几路），还会撞上「每站一个检测器」的假设。**每帧仍只有一行**：帧级的统计量、
门限、命中、段号、频段一字不动，帧级 Pd / Pfa、ROC、特征提取、识别、事件都不受影响；开了只多 `subband_hit` 与 `subbands` 两个键。

### 9.1 逐帧算法（C++ `engine/src/subband.cpp` 与 Python `algos/reference/subband.py` 同序）

```
① P_j   = |DFT(w·x)_j|²，j ∈ 检测频段（M 个频点）；w 为周期 Hann 窗（float32 窗值，与特征提取同）
② 每个频点一个长 W 的环（W = noise_window_frames）：环空先入环；环变过才重算 n̂_j = 中位数 / ln 2；
   任一频点连续超过 W 帧没入环，计一帧陈旧
③ 多级块：第 l 级块宽 S_l = K0·2^l ≤ M，从频段第一个频点起切、保留不满的尾块；检验总数 N = 各级块数之和
   Λ_b = Σ_{j∈b} P_j / Σ_{j∈b} n̂_j，命中 ⇔ Λ_b > η(|b|, pfa / N)
④ 标记：块命中、且它下面任何一级的块都没命中（第 0 级命中即标记）
⑤ 成簇：标记的频点连成串，间隙 ≤ K0 的串并成一簇
⑥ 连接：先关掉超过 merge_gap_frames 没续上的段；每簇对每个开着的段的最近 64 帧的频段并集比，
   重叠（容差 K0 个频点）最多的连上，平局取段号小的，没有就开新段；只往前连，从不重编段号
⑦ 删截：标记的频点两边各扩 2 个频点不入环，其余频点各自入环（满则弹最旧）
```

**门限是精确的，不是矩匹配**。Hann 窗让相邻频点相关：复系数的相关是 Toeplitz `[1, −2/3, 1/6]`。S 个频点的块统计量
在 H0 下是 `Σ λ_i E_i / S`（λ_i 是 S×S 相关阵的特征值、E_i 独立单位指数），尾概率用 Lugannani–Rice 鞍点近似求，
η 按 `pfa / N` 反解（Bonferroni 分摊）。引擎的特征值由久期方程求（相关阵 = (8/3)(T² + (1/16)(e₁e₁ᵀ + e_Se_Sᵀ))，
T 为三对角 Toeplitz，按奇偶拆开），Python 参考用 numpy 的通用特征值；S = 1…153 对 numpy 差 2.2e-15。
原型研究（第 0 步）实测：矩匹配的 Gamma 门限在深尾部偏松——对蒙特卡洛，1e-3 处 1.5 倍、1e-5 处 3.7 倍。

**为什么连「最近 64 帧」**：对段的全体频段并集连接会棘轮——golden-02 的图传段开了 1 s，每个贴近并集的跳频簇都被连进来，
并集再扩一点，最终罩住全部五个跳频点；只对上一帧连接，非视距衰落让频段一帧一帧闪，S09 碎成 8335 段。最近 64 帧折中两者。

dBm：`band_power_dBm = 10·log10(ΣP / (nfft·Σw²))`、`noise_dBm` 同式（未标定时两键都省）；`snr_dB = 10·log10 Λ`。

### 9.2 评价（`segments_tf`，`engine/src/evaluation.cpp` 与 `algos/reference/evaluate.py` 同序）

时间 × 频率**一对一**配对，字段见 `docs/display-products.md` §5.5：

- 段 = 分子带段号相同的簇；时间 [首帧, 末帧 + 一帧)；频段取**核心**——在该段至少一半的帧里命中的频点（没有就取全部）；
- 真值频段 = 名义中心 + `cfo_Hz` ± `bw_Hz/2`。**不含场景 `offset_Hz`**：`truth.jsonl` 里没有它；机型预设没有偏移，单音类的偏移小于半带宽；
- 候选：时间重叠比与频率重叠比（都对较短 / 较窄的一方）都 ≥ `match_overlap`（0.5）；按两比之积贪心配对，平局按真值时刻、辐射源、段号；
- **真值频段落在检测频段内不足 `match_overlap` 的行计 `truth_partial`、不进分母**：频率重叠比够不到配对条件，
  检测器怎样都配不上。回归首跑时 s05 因此差 0.034——S-FHSS 的 0 号信道 2403.97 MHz、204 kHz，只有 33% 在 2404–2476 MHz 内。
  截断频段不行：边沿的包只露出一小块，碎成好几段，碎片约 11%。

### 9.4 已知行为

1. **虚警段大半在突发开关的边沿**：矩形门控的突发在开关那一帧把能量泼到全带，s02 的 92 个虚警段里 61 个落在真值起止 2 帧以内。
   能量是真的，只是不在真值频段里，照实计虚警段。
2. **强信号的谱肩**：30 dB 的图传，带外裙边单独成段，计虚警段。
3. **时频面上连在一起的信号分不开**：跳频点落在图传的谱肩里（golden-02 的 24 个）、或同时同频（被并掉）——能量检测分不开，照实计。
4. **粗块定位粗**：只有粗块命中时，簇的频段就是那个块宽（K0·2^l 个频点）。
5. **暖机**：每个频点的环在头 W 帧里从 1 帧涨到 W 帧，这期间虚警率高于目标；判据只看暖机之后。
6. **浏览器里抽稀**：6 s 的 10 MS/s 任务约 1.7 万行子带命中行，超过单次响应 16 MiB，浏览器按服务端建议的步长抽稀并在页头写明（同帧级，D-063）。
   评价器读的是文件，不抽稀。
7. **代价**：每个频点一个有序环，入环是 O(W) 的插删；80 MS/s 下每秒 78125 帧 × M 个频点，是本组件里最重的一项。
