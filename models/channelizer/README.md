## 1. 做什么

把一路宽带复基带 IQ 切成 `channels` 条等宽子信道，**临界抽取**（抽取比 = 子信道数），
本期**只输出其中一路**（`select_channel`）。

```
fs_out     = fs_in / channels
中心频率   = 输入中心 + (select_channel − channels/2) · fs_out
可用子带   = ±0.4 · fs_out（见 §7 第 1 条）
```

一句话的代数（推导见 08 报告 §8、`matlab/ref/cuav_pfb_cycle.m` 头注）：

```
y_k[m] = Σ_n h[n]·x[n0−n]·exp(−j2πk(n0−n)/M),   n0 = m·M + gd
       = Σ_r exp(+j2πk·r/M) · u_r[m]              （gd 是 M 的整数倍，常数相位恒为 1）
u_r[m] = Σ_q h[r+qM]·x[n0−r−qM]                   （第 r 条多相支路）
```

`Σ_r exp(+j2πkr/M)·u_r` 就是**未归一的逆 DFT**，`.m` 里写 `M * ifft(...)`。
每支路恒 29 个抽头 —— **每输出样点每子信道 29 次乘加，与 M 无关**（与 DDC 的「恒为 ≈27」同一句话）。

## 2. 参数

| 名 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `channels` | number | 8 | 子信道数，取值须在冻结表内（2 / 4 / 8 / 16 / 32 / 64），且输入采样率须能被它整除 |
| `select_channel` | number | 4 | 输出哪一路。**相对输入中心从低到高编号**，`channels/2` 那一路是零频 |
| `fir_version` | enum | `pfb_v1` | 多相原型滤波器的版本 |

**`select_channel` 的缺省是 `channels/2` 而不是 10 报告 §3.7 写的 `0`**（本卡对报告的一处偏离，
已回填 10 §3.7）：按低→高编号，`j = 0` 指的是**带边（±fs/2 绕回）那一路** ——
临界抽取滤波器组里它合法，但作缺省最差。`channels/2` 就是零频那一路，与 S4 中心重合，
「S5 中心 = S4 中心」肉眼可核。改了 `channels` 要一并改它（目录里的说明写着这句）。

界面编号 `j` 与原始 FFT 下标 `k` 的换算在封装层里：`k = (j + M/2) mod M`。

## 3. 时间锚：输出样点 m ↔ 输入样点 m·M

08 报告 §8 口径一的逐样点形式。做法与 DDC 相同：**把换向器相位初值置为群时延 `gd`**。
于是下游三处断言一行不用改 —— `FeatureExtractor` 的 `start_sample == frame_index·nfft`、
块连续性检查、S4/S5 产品索引的 `t0_s = 0`。

输出条数的闭式（收尾丢不满一个输出周期的那几个输入样点，**不补零**）：

```
n_out = (n_in − 1 − gd) / M + 1      （n_in > gd 时；整数除法）
```

演示夹具实测：`60000000` 入 @ 10 MS/s → **`14999986`** 出 @ 2.5 MS/s，与闭式相符。

## 4. 抽头数为什么是 `N = M·T + 1` 且 `T` 取偶数

两个要求本来是冲突的：

- 08 §8 口径二要群时延是**整数个输入样点**（`gd = (N−1)/2`）→ N 必须**奇数**；
- 多相分解要 N 是 **M 的倍数**（M 是偶数）。

`N = M·T + 1`、`T` 取偶数同时满足两者，并且额外带来一件好事：
`gd = M·T/2` 是 **M 的整数倍**，于是 §1 里那个常数相位 `exp(−j2πk·gd/M) ≡ 1`，
**FFT 组的输出不需要任何逐信道修正**。规划阶段实算验证过：`max|exp(−j2πk·gd/M) − 1| = 6.9e-15`。
T 取奇数则这个相位不为 1，三方还得逐字对齐一遍 —— 没有必要。
装载时零填充到 `pad_to = M·(T+1)`，让 M 条支路等长。

`scripts/design_pfb_fir.py` 的自检里因此有一条**本表独有**的断言：`gd % M == 0`。

## 5. 系数表

真理源 `models/channelizer/fir_pfb_v1.json`，由
`uv run --quiet --with scipy --with numpy python scripts/design_pfb_fir.py --write` 设计并冻结；
引擎侧副本 `engine/src/pfb_taps.cpp` 由 `uv run --quiet python scripts/gen_fir_taps.py --kind pfb` 生成，
单测逐位核对并比对表的 sha256（「改了表忘了重生成」在对拍之前就红）。

指标：通带 `0.4·fs_out`、阻带 `0.5·fs_out` ≥ 60 dB，`sum(h) = 1`（子信道中心的单音过滤波器组后幅度不变）。
`T = 28` 对六档通用：

| M | N = 28M+1 | gd = 14M | gd mod M | 阻带 | 通带纹波 |
|---|---|---|---|---|---|
| 2 | 57 | 28 | 0 | 62.27 dB | 0.1316 dB |
| 4 | 113 | 56 | 0 | 62.47 dB | 0.1293 dB |
| 8 | 225 | 112 | 0 | 62.51 dB | 0.1289 dB |
| 16 | 449 | 224 | 0 | 62.52 dB | 0.1289 dB |
| 32 | 897 | 448 | 0 | 62.53 dB | 0.1290 dB |
| 64 | 1793 | 896 | 0 | 62.54 dB | 0.1281 dB |

**只存半表**（含中心抽头），装载时镜像展开再零填充：等波纹设计的输出不保证逐位对称，
存全表会让三方的群时延在 1e-17 级上对不齐（与 DDC 同一条理由）。

主设计走 scipy（BSD，任何机器可复算）。**M-2 踩过的坑在这里也必须防**：
scipy 的 `remez` 用周/样点（量程 0…0.5），MATLAB 的 `firpm` 用归一化到奈奎斯特（量程 0…1），
**差一个 2**；设计脚本的自检拿自己那套带边去量阻带、照样全绿。所以验收里必须有**物理量**的锚点
（§7 的解析锚点与 §9 的演示夹具），不能只靠脚本自检。

## 6. 三方互证：两个尺度，两条判据

| 尺度 | 谁与谁 | 判据 | 实测 |
|---|---|---|---|
| 算法核（double 进 double 出） | Coder 产物 ↔ MATLAB `.m` ↔ Python 参考 | **rel ≤ 1e-9**（06 §9D） | Coder 对 MATLAB **1.38e-16**、MATLAB 对 Python **5.70e-13**、Coder 对 Python **5.70e-13** |
| 组件（输出存 `complex64`） | 引擎组件 ↔ `algos/reference/channelizer.py` | rel ≤ 1e-6 | **0（逐位相同）** |

组件那一层用 1e-6 不是放宽铁律 10：`cuav::Complex` 是 `std::complex<float>`，eps 就是 1.2e-7，
**拿组件输出去套 1e-9 是套不上的**，那不是算法不准，是存储精度的下限。

**逐位相同不作承诺**（与 M-2 的 DDC 不同）：MATLAB 的 `fft` 走 FFTW、Coder 生成的是自带的基 2 实现、
numpy 走 pocketfft，三家的蝶形次序与旋转因子求值各不相同。组件尺度这次恰好逐位相同，
那是 float32 舍入把 5.7e-13 的差吃掉了，不是承诺。

**共享输入必须共享比特不能共享公式**（M-3 第 5 步踩实过）：黄金文件把核对窗口写成**显式数据**，
三方谁也不再各自按闭式算一遍输入。反例是真的发生过 —— 三方各按 `sin(0.00021n² − 0.07n + 0.9)`
算输入，clang `-O2` 把多项式收缩成 FMA，n = 4026 处相位差 4.5e-13，两个 `sin` 结果跨了 float32
的舍入边界、差一个完整 ulp（1.49e-8），再经滤波器 3823 倍的相消放大成 **1.5e-9**。
改成共享比特之后，同一条对拍从 1.5e-9 降到 **5.7e-13**。

Python 参考 `algos/reference/channelizer.py` 有意写成**直接式**（逐路乘 `exp(+j2πkn/M)` 再求和），
不走多相也不走 FFT —— 第二实现要独立才有意义。`--selftest` 跑六项物理自检。

## 8. 已知边界

1. **临界抽取的固有后果：相邻子信道的过渡带折进本路外侧 20%**。原型的通带是 `0.4·fs_out`、
   阻带从 `0.5·fs_out` 起，于是 `±0.4·fs_out` 之外到奈奎斯特那一段既有本路的过渡带、
   又有邻路折回来的东西。**可用子带是 ±0.4·fs_out，不是 ±0.5·fs_out**。
   要无混叠的全带就得过采样滤波器组（抽取比 < M），本期不做。
2. **本期只输出一路**（10 §3.7 明写）。全部子信道并行输出是全仓第一个多输出组件，
   要给 `TapPlacement` / `tapAt` / `tapOpId` 加第二根实例轴、并改产品目录命名，留后。
3. **`channels` 只有六档**（2/4/8/16/32/64）。查不到不静默顶替也不取最近一档，
   报错并列出表内可取的值（铁律 15）；`channels = 1` 不是「不抽取」而是无意义配置，
   要不做信道化就**旁路这个槽位**，错误报文里直说了这句。
4. **输入采样率须能被 `channels` 整除**（08 §8 口径一）。这条在收到第一块时查，
   与 DDC 的 `fs_in % decim` 同法。
5. **混合增强模式下 `AddMixer` 的限制更紧**：它要求两路采样率与中心频率一致，
   而信道化把 S4 切碎了 —— 回放背景得正好等于某一路子信道。本期同样只保证**报错清楚不静默**，
   不做反推。DDC 已有同一条限制（`models/adc-ddc/README.md` §8.3）。
6. **多级抽取（`decim > 20`）不在本期**（用户 2026-09-16 拍板推迟）：它要往
   `models/adc-ddc/fir_lp_v1.json` 加档，而 `engine/tests/golden/ddc.json` 对着那张表的 sha256，
   那是一次真正的基准变更；本期最高只有 demo-02 的 10 MS/s，`decim` 到 20 绰绰有余，没有场景用得上。

## 9. 演示夹具

`tests/regression/diagrams/chain-demo-02-chan.json`（`npx tsx src/chain/examples/_gen.ts demo-02-chan` 生成）：
demo-02 宽带场景，10 MS/s @ 2441 MHz，`channels = 4`、`select_channel = 2`（零频那一路）
→ **S5 = 2.5 MS/s @ 2441 MHz**。观测点取 S3 与 S5 两个（**不取 S4**：DDC 旁路时 S4 的锚点顺链
下滑到信道化那一节，与 S5 同节点同口，读数会一模一样）。

取零频那一路而不是图传那一路，是因为它能演示的更多：图传（2437.5–2439.5 MHz）整个落进相邻子信道，
五个跳频点里三个（−0.3125 / −0.625 / +0.625 MHz）落在本路 ±1.0 MHz 的通带内、留 375 kHz 余量。
于是 S5 的瀑布上 0.5–2.5 s（只有图传）是底噪、3–4.5 s（只有跳频）是突发串 ——
**演示的是「把两个辐射源分开」而不只是「选出一段频率」**。

实测（macOS，原型阶段验证值；6 s、墙钟 8.4 s、实时因子 0.71）：

| 量 | 实测 |
|---|---|
| 通带内逐带一致（±1 MHz 带内平均功率，S3 对 S5） | **+0.07 / +0.04 / +0.10 dB**（全静默 / 只有图传 / 只有跳频） |
| 三个带内跳频点的峰值（S5 对 S3） | 差 **≤ 0.09 dB** |
| 图传：自己那 2 MHz 带内 → 落进本路的 | −47.10 → **−72.71 dBm**（低 25.6 dB） |
| 带外那两跳（混叠到 −0.9375 / −0.3125 MHz） | S5 读 **−101.5 / −102.8 dBm** |
| 识别 `rc_hopping` 准确率 / 突发级 | **0.978** / `pd_segment = 1.0`、150/150 全匹配 |
| 帧级 Pfa | **0.52** ← 见下 |

**三条要照实说的**：

1. **图传那 25.6 dB 是源端定的，不是信道化定的**。S3 在同一 ±1 MHz 带里读到的就是同一个数
   （差 0.04 dB）—— 落进本路的是图传自己 4 阶巴特沃斯带限的裙边（D-069 记过「阻带非砖墙」），
   信道化在自己的通带里一进一出没有任何额外贡献。不吹成「信道化压了 25 dB」。
2. **带外两跳的真实阻带抑制在这里量不出来**：S3 在同一时隙、同一（混叠后）频点上已经有
   −94.4 / −97.8 dBm —— 那是 3 ms 门控突发自己的 sinc 裙边，S5 读到的比它还低
   （差值主要是 4 倍 RBW 的 6 dB）。量到的是突发的谱不是滤波器的谱。
   **纯单音下的 63.64 dB 邻道抑制（§7）才是滤波器的数。**
3. **帧级 Pfa 0.52**：图传裙边在本路里把带内功率抬高 10.5 dB（−83.15 → −72.68 dBm），
   能量检测器照样触发，而图传的真值在带外（`truth_out_of_band = 102`，D-067 ④）不计入分母，
   于是这些帧算虚警。**这是源端带限不是砖墙的真实后果，不是信道化的缺陷，不调参去掉它**（铁律 10）。

检测器频段随 `fs_s5` 自动收窄到 ±1.125 MHz（`web/src/chain/compile.ts` 早已如此）。

**另一份夹具** `tests/regression/diagrams/chain-demo-02-dsp.json`（C-10）把三级 DSP 一起打开：
接收滤波 → DDC → 信道化，10 → 5 → 2.5 MS/s，S3 / S4 / S5 一次跑出三种采样率。
那一份用 `channels = 2`、`select_channel = 1`（可用子带 ±1.0 MHz，正对图传）；
实测图传带内功率沿链 −47.163 → −47.227 → **−47.161 dBm**，即信道化这一级差 **+0.065 dB**、
整条三级链累计 **+0.002 dB**。

## 10. 为什么这一件走 Coder

D-036 定的 DSP 路线是 MATLAB Coder 生成 C，M-2 的 `DDC` 因工程取舍手写（算法核约 60 行，
封装层本来就得手写，Coder 省不下多少）。本件不同：多相分解 + 换向器 + FFT 组，
**「重写等于重新承担一次验证成本」在这里是成立的** —— 工具箱的 `ifft` 与 `filter` 的语义
（含分块的初末条件）由 MathWorks 定义并验证，自己写一遍就要自己再验一遍。

Coder 侧的三个非缺省配置与理由记在 `matlab/coder/README.md`；产物的可复现性、
文件头不带时间戳、`rtwtypes.h` 自足（不 `#include "tmwtypes.h"`）这三件也在那里。
产物的完整性由 `engine/src/coder_provenance.cpp` 编进来的 sha256 守着
（`engine/tests/test_coder_provenance.cpp` 重算一遍：25 / 25 相符）。

**许可**：产物文件头带 MATLAB 学术许可条款，用户 2026-09-16 澄清本项目属学术用途、据此可用（D-070）。
**产物若将来随交付物出去，需按实际用途另行核实** —— 这一条留档备查。
