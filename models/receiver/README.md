# 模型卡：接收机前端 `ReceiverFrontEnd`、ADC 量化 `AdcQuantizer` 与接收滤波 `RxFilter`

**组件**：实现在 `engine/src/receiver.cpp`，声明在 `engine/include/cuav/components/receiver.h`。
**分级**：均为 M3 施加 / E2 工程等效 / V2。**依据**：04 §7.5（接收机前端等效模型十项）、§7.6（ADC
七项）、§5.4（S2 与 S3 观测点）、附录 A（接收机首期必做「滤波、增益、噪声、频偏、相噪、IQ 不平衡、
削顶」）；概念模型 EM-B-11 §10.1（热噪声与噪声系数）、EM-B-12 §10.1（参考温度与热噪声谱密度）、
EM-S-02 §11.2（`overload_flag`）；决策 D-051、D-050 问题 ②③、D-047（功率单位 mW）。
**落地**：2026-09-07，C-2；`RxFilter` 2026-09-16，M-3（D-071），见 §8。

## 1. `ReceiverFrontEnd` 算什么

按顺序逐样点施加五项，不改变流长度：

```
n  ~ CN(0, N0·fs)                              等效输入热噪声（noise_mode = thermal 时）
y1 = 10^(gain_dB/20) · (x + n)                 总增益（噪声折合到输入，故加在增益之前）
y2 = y1 · exp(j·2π·lo_offset_Hz·k/fs)          本振频偏，相位累加器跨块连续
y3 = K1·y2 + K2·conj(y2)                       IQ 幅相不平衡
y  = y3 + sqrt(dc_offset_mW/2)·(1 + j)         直流偏置
```

`K1 = (1 + g·e^{jφ})/2`、`K2 = (1 − g·e^{jφ})/2`，`g = 10^(iq_gain_imbalance_dB/20)`、
`φ = iq_phase_imbalance_deg`。这一形式与 MATLAB `comm.IQImbalance` 同定义，M-5 的参考模型
可以直接对拍。镜像抑制比为 `10·log10(|K1|²/|K2|²)`。

**不做的**：接收滤波（幅频响应与群时延是 M-3 的 Coder 产物 `RxFilter`，串在本组件之前）、
相位噪声、增益压缩、自动增益控制的动态过程、互调与阻塞。这些是 04 §7.5 里明确可用「输入输出
曲线或等效项表达」的部分，随 P3 与 M-5。

## 2. 噪声底：为什么与场景帧共用同一个常数

D-050 问题 ② 的拍板结论是**典型链路里接收机噪声由噪声系数生成，取代手兑噪声**。此前噪声是
独立 `NoiseSource` 加 `AddMixer` 按用户给的绝对电平兑出来的，「噪声系数」这个演示时必讲的参数
在系统里没有落点。

```
N0(dBm/Hz) = −174 + 10·log10(T / 290) + nf_dB
噪声总功率(dBm) = N0 + 10·log10(fs)          复基带噪声占满整个复奈奎斯特带
```

−174 dBm/Hz 取自 `geo/link_budget.cpp` 的 `thermal_noise_dBm_per_Hz()`，**只有一处定义**。
290 K 的 kT 实为 −173.975 dBm/Hz，工程惯例四舍五入到 −174；这是已有的口径，本组件跟随它而不是
另立一套，好处是场景参数帧里的链路噪声底读数与这里实际注入的噪声**逐项一致**，界面上两个数
不会打架。代价是与物理值差 0.025 dB，写在这里备查。

**这条改动不动任何既有基准**（铁律 10）：本组件是新增件，既有示例框图一个字没改，仍然手兑噪声。
两者数值上也是自洽的——切片 ② 示例里手兑的 −111 dBm，正是 `−174 + 6 + 10·log10(500000)`
= −111.01 dBm，即 500 kS/s、噪声系数 6 dB 的解析值。

`noise_mode = none` 供混合增强模式使用：实测背景片段自带接收机噪声，再注入即重复计入
（04 §7.8「实测背景 + 合成目标」）。

## 3. `AdcQuantizer` 算什么

```
A = 10^(full_scale_dBm/20)          满量程复单音的幅度
q = 2A / 2^bits                     量化步长
code = clamp( round(v/q), −2^(bits−1), 2^(bits−1) − 1 )
v_out = code · q                    I、Q 各自独立量化
```

正端比负端少一个码，是二进制补码的常规。满量程复单音的量化信噪比为 `6.02·bits + 1.76 dB`
（推导：信号功率 `A²`，两个分量的量化噪声共 `2·q²/12 = q²/6`，比值 `6A²/q² = 1.5·2^(2·bits)`）。

输出仍是 float32 的 mW 幅度，不是整数码：量化只体现为取值离散化。`full_scale_dBm` 把码范围
与物理功率绑定，与 D-047 的功率单位约定一致。

**未实现**：采样时钟偏差、丢样与不连续注入、量化抖动。前两项是 04 §7.6 的可选项，
`rounding` 留了枚举位给抖动。

## 4. 削顶：为什么是标记不是降级

D-050 问题 ③ 的拍板结论：

| 层次 | 处置 |
|---|---|
| 逐块 | 削顶样点数写进 `BlockMeta.clip_count`，并在 `state_reasons` 追加 `adc_clip:<n>`。**四态不变** |
| 观测点索引 | `clipped_samples` 累计（`docs/display-products.md` §2），界面在页头写「削顶 n 样点」 |
| 全程 | 收尾时若削顶比例超过 `degrade_clip_ratio`（缺省 0.01），组件状态才标 `degraded` |

理由与 08 报告 §9.5 对整数样点时延跳变的处置相同：削顶是被显式建模的效应，把它标成降级会让
整个任务的结果四态变成降级，从而淹没真正的降级信号。但持续过载的数据对下游检测识别确实不可信
（EM-S-02 §11.2 的 `overload_flag` 同理），所以比例失控时仍要降级。

## 5. 参数与取值来源

`ReceiverFrontEnd`：

| 参数 | 单位 | 缺省 | 来源 |
|---|---|---|---|
| `noise_mode` | — | `thermal` | 由典型链路视图按模式填（混合模式为 `none`） |
| `nf_dB` | dB | 必填 | 场景 `sites[].receiver.nf_dB` |
| `reference_temperature_K` | K | 290 | EM-B-12 `reference_temperature`，工程常用值 |
| `gain_dB` | dB | 0 | 用户设置 |
| `lo_offset_Hz` | Hz | 0 | 用户设置 |
| `iq_gain_imbalance_dB` / `iq_phase_imbalance_deg` | dB / deg | 0 | 用户设置；实测分布随 P3（DroneRFa 是唯一的正交不平衡校准素材，D-018） |
| `dc_offset_mW` | mW | 0 | 用户设置 |

`AdcQuantizer`：

| 参数 | 单位 | 缺省 | 来源 |
|---|---|---|---|
| `bits` | — | 14 | 用户设置；枚举 8 / 10 / 12 / 14 / 16 |
| `full_scale_dBm` | dBm | 必填 | 用户设置，由频率计划面板按预估峰值电平加峰均比余量给建议 |
| `rounding` | — | `nearest` | — |
| `degrade_clip_ratio` | — | 0.01 | assumed |

**除 `nf_dB` 来自场景外，其余缺省都是 assumed**。甲方给出实际接收机指标后按 04 §11.3 标定。

## 6. 验证

`engine/tests/test_receiver_chain.cpp`：

- 噪声底解析锚点：`nf = 6 dB` 时 −168 dBm/Hz；10 MS/s 下 −98 dBm；500 kS/s 下 −111.01 dBm
  （与切片 ② 手兑值一致）；温度 580 K 时 +3.01 dB；
- 噪声蒙特卡洛矩校验（铁律 9）：功率相对误差 < 1%、I/Q 标准差比 1 ± 0.02、I/Q 互相关 < 0.01
  （样本 2²⁰）；
- `noise_mode = none` 不注入噪声，增益按 dB 施加；
- IQ 不平衡的镜像抑制比等于 `|K1|²/|K2|²` 的解析值（0.5 dB + 5° 时约 25.7 dB）；
- 本振相位跨块连续：块长 4096 与 512 两种切法结果最大偏差 < 1e-6；
- ADC 量化信噪比在 8 / 12 / 14 位上与 `6.02·bits + 1.76 dB` 差 < 0.5 dB；
- 过驱整块削顶：计数、块元数据、理由都对，且**四态仍是 valid**；收尾才降级；
- 削顶比例 1% 低于 5% 阈值时收尾不降级；
- 零输入时输出精确为零，不造出假直流；
- 串链：天线 + 前端后 S2 上的信号功率与噪声功率各自等于解析链路预算（噪声差 < 0.05 dB）；
- 削顶累计经 `ObservationTap` 写进索引 `clipped_samples`。

## 7. 适用范围与不适用

**适用**：单通道、复基带、慢变增益的接收链路等效；用于演示噪声系数、增益、量化位数与满量程
如何影响频谱底噪、动态范围与检测性能。

**不适用**：器件级杂散树、互调产物、完整 AGC 环路、相位噪声对相干解调的影响、频率相关的噪声
系数曲线。04 §7.5 明确「首期不进行晶体管级、混频器器件级和完整杂散树仿真」。

本组件产出的 S2 与 S3 观测点是**等效**观测点：它们与真实接收机同一位置的信号有相同的统计特征
量级，但不逐点对应。04 §11.1 的验证目标正是「不是证明内部每个参数都等于真实物理参数」。

## 8. 接收滤波 `RxFilter`（M-3，D-071）

**组件**：封装层 `engine/src/rx_filter.cpp`，声明 `engine/include/cuav/components/rx_filter.h`；
**算法核是 MATLAB Coder 生成的 C**（`matlab/ref/cuav_rx_fir.m` → `models/receiver/coder/*.{c,h}`，11 个文件）。
**分级**：M3 / E2 / V2，`model_id = EM-B-11`。**依据**：04 §7.5 与附录 A 的「滤波」、§15.2 算例 5
（接收滤波和群时延）；08 报告 §8 口径二、§13 三层分工。

### 8.1 做什么

不抽取的线性相位 FIR，只改幅频响应与群时延，不改采样率也不改中心频率。
抽头奇数，**群时延 `(N−1)/2` 个输入样点在这一层扣除**（08 §8 口径二）：
输出样点 m 对应输入样点 m，`start_sample` 自 0 起严格连续。不扣的话下游三处断言当场破
（`FeatureExtractor` 的 `start_sample == frame_index·nfft`、块连续性检查、S4 索引的 `t0_s = 0`）。

收尾**不补零**，末尾少 `(N−1)/2` 个输出样点 —— 补出来的输出是用根本没采到的数据算的（铁律 15），
且会在谱末尾留一段淡出被下游读成真实电平变化。首端的零前史无法避免（`start_sample` 自 0 起的代价），
**不对称是有意的**，与 DDC 同一条口径。

### 8.2 参数与查表

| 名 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `bw_Hz` | number | **必填** | 通带宽度（复基带双边占用） |
| `fir_version` | enum | `rx_v1` | 抽头版本：过渡带 0.05·fs、阻带 ≥ 60 dB、奇数抽头 |

冻结表按**相对通带** `bw_rel = bw_Hz / fs_in` 建档（`models/receiver/fir_rx_v1.json`，七档 0.2…0.8，
抽头 57 / 55×6，群时延 28 / 27）。`bw_rel` 上不去 0.9：过渡带会顶到奈奎斯特。

**采样率要到第一块才知道**，所以查表推迟到首块执行，与 DDC 的 `fs_in % decim` 同法。
查不到**不静默顶替、也不取最近一档**（铁律 15），报错并列出该采样率下可取的值，例如：

> `bw_Hz = 6400000 与输入采样率 10000000 Hz 的比值 0.64 不在冻结抽头表内；该采样率下可取的 bw_Hz 是
> 2000000 / 3000000 / … / 8000000 Hz`

选 `bw_Hz` 而不是相对量，是因为场景里**早就有这个字段**：`sites[].receiver.bw_Hz`
（demo-02 是 8 MHz / 10 MS/s）自 G-2 起被解析、校验，然后**没有任何模型用它**——
与 C-2 之前的 `antenna.pattern` 是同一种情形。`RxFilter` 是它的第一个消费者。
按 D-054 的 `FROM_SCENE` 机制由场景逐站带出，留 C-10。

### 8.3 排在哪里

**本组件排在 `ReceiverFrontEnd` 之前**（`engine/include/cuav/components/rx_filter.h` 的头注记了缘由）：
前端注入的等效热噪声因此不被它整形，**S2 的底噪仍是 −174 + nf + 10·log10(fs)** ——
这个等式有三处别的地方在依赖（频率计划的 `adc_floor` 检查、模型卡 §2、slice4 的 S2 断言）。
放在前端之后会把底噪按滤波器的等效噪声带宽压下去，那三处会一起对不上。

### 8.4 解析锚点（`engine/tests/test_rx_filter.cpp`，标准算例第 5 项）

| 量 | 实测 | 判据 |
|---|---|---|
| 通带增益（`bw_rel = 0.5`，六个通带频点） | 最大偏差 **0.148 dB** | < 0.2 dB（纹波） |
| 阻带抑制（五个阻带频点） | 最差 **61.13 dB** | ≥ 60 dB |
| 冲激对齐：输入 `n0` → 输出峰值就在 `n0`（**逐档七个都验**） | **偏差 0 样点** | 0 |
| 输出条数 = 输入条数 − 群时延 | 逐值 | 逐值 |
| 块长无关、`reset()` 复现 | 逐位相同 | 逐位 |

### 8.5 三方互证

| 尺度 | 谁与谁 | 判据 | 实测 |
|---|---|---|---|
| 算法核（double） | Coder ↔ MATLAB `.m` ↔ Python | **rel ≤ 1e-9**（06 §9D） | Coder 对 MATLAB **8.3e-16**（末态 zf **9.4e-20**）、对 Python **7.7e-16** |
| 组件（`complex64`） | 引擎 ↔ `algos/reference/rx_filter.py` | rel ≤ 1e-6 | **0（逐位相同）** |

MATLAB 侧还顺手把**状态交接**钉住了：`filter` 的末态 `zf` 就是卷积结果落在本块之后的那一截
（`zf(j) = conv(x,h)(L+j)`），封装层的分块无关性靠它，两条路在生成器里当场互证（1.4e-16）。
细节与「为什么不承诺逐位相同」见 `matlab/README.md`。

### 8.6 已知边界

1. **缺省旁路**（C-10 已把它串进框图页：`rx_fe` 卡片里的一行子环节，行尾有自己的旁路勾选框）。
   缺省不接的理由是接上它会改变每一条既有链路的产品，而本期没有场景需要它。
   在这条链上它的效果也确实有限：三份示例场景的通带都覆盖了全部辐射源，
   而前端的热噪声是在它**之后**注入的（见 §8.3）—— 于是它能滤掉的只有带外辐射源与
   带内辐射源自己的裙边。实测：加上它之后 S3 在全静默窗口上与不加时**逐位相同**，
   通带内逐 bin 中位差 −0.048 dB，阻带中位 −1.897 dB（滤掉的是图传那条巴特沃斯裙边）。
2. **`bw_rel` 只有七档**，且是相对量：同一个 `bw_Hz` 换了采样率就可能查不到。这是有意的 ——
   滤波器的形状由相对带宽决定，按绝对带宽建表会让表随采样率组合爆炸。
3. **不做**相噪、增益压缩、AGC 动态、频率相关的噪声系数（M-5 / 04 §7.5 的「首期不做」）。
