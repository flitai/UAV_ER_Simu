## 0. 先说清楚这三件不是什么

**它们是「测向与定位算法的统计模型」，不是被测的测向与定位算法。**

`DirectionFinder` 不看 IQ。它从链路参数帧里取**真值方位**与电平，按噪声系数算信噪比，
按误差预算算出 1σ，抽一个高斯样本作为「量测方位」。`ToaEstimator` 同理，取真值时延加噪。

取真值合法，依据是 01 §6.2（模型的输入可以是真值）：M2 效应级模型的定义就是「不复现物理过程，
只复现物理过程的统计结果」。04 §5.2「真值只进评价器」约束的是**被测的 M3 算法**
（检测器、识别器），本线是新加的观测量生产者，不参加检测识别的评价。

代价是三件事必须声明，缺一不可：

1. 溯源里 `model_layer = M2`、`model_level = E2`、`credibility = V2`；
2. 每一行报告带 `truth_consumed = true`；
3. **本卡这一句**：所有散布来自建模的误差预算，**不代表任何真实测向或定位设备的实测性能**。
   评价页上的定位指标是「模型自洽性检查」（抽样散布与声称的 σ 是否一致，即 01 §8 的跨层一致性），
   不是「这套设备能定多准」。

05 P1 的阵列估计器（MUSIC / 相位干涉）将来从 `ArrayIQStream` 出发算方位，输出**同一个端口**
替换 `DirectionFinder`，框图形状与下游一件不改；那时 `truth_consumed` 才变成 `false`。
P2 的 IQ 相关到达时间同理替换 `ToaEstimator`。

## 1. `DirectionFinder`：单站测向（EM-S-05）

### 1.1 算什么

```
Prx  = tx_power + G_tx + G_rx − path_loss        （场景 + 帧）
N    = noise_floor_dBm_per_Hz + 10·log10(B)      （帧；B = 站的 fs_Hz）
SNR  = Prx − N
σ_θ  = √(σ_method² + σ_snr² + σ_cal² + σ_att² + σ_mp² + σ_mix²)
方位 = wrap360(真值方位 + bias + σ_θ · N(0,1))
```

信噪比项 `σ_snr = σ_ref · √(SNR_ref_lin / max(SNR_lin, 1))`。与 emcore 的 `σ_base/√SNR` 同形，
只是把参考点显式化——写成 `σ_base` 时「它对应多少 dB」藏在常数里，换个体制没法解释。
`SNR < 0 dB` 时线性值钳到 1，σ 不发散。

### 1.2 七个分量与缺省值

| 分量 | 参数 | 缺省 | 含义 |
|---|---|---|---|
| 方法固有 | `sigma_method_deg` | 1.5° | 测向体制本身的分辨力 |
| 信噪比 | `sigma_snr_ref_deg` @ `snr_ref_dB` | 2.0° @ 10 dB | 见上式 |
| 标校残差 | `sigma_cal_deg` | 0.5° | 标校后的剩余系统误差 |
| 平台姿态 | `sigma_att_deg` | 0.3° | 站址方位基准误差 |
| 多径 | `sigma_mp_los_deg` / `sigma_mp_nlos_deg` | 0.5° / 5.0° | 按帧的 `line_of_sight` 二选一 |
| 同频混叠 | `sigma_mix_deg` | 8.0° | 只加在被压住的那个源上 |
| 系统偏差 | `bias_deg` | 0° | **不进方差**，直接加在方位上 |

**已知简化（必须写在这里）**：D3 的遮挡接入之前，帧里的 `line_of_sight` 恒为真，
因此 `sigma_mp_nlos_deg` **实际不生效**。缺省值全部是工程取值，非甲方清单，属原型阶段取值（D-028）。

### 1.3 同频混叠的判据

三个条件缺一不可：① 两源的**占用带**重叠（`|Δf| < (B_i + B_j)/2`）且都落在本站接收带内；
② 对方更强；③ 电平差 `< mixture_separation_dB`（缺省 10 dB）。
被判混叠的那一行加 `σ_mix`、标 `mixture = true`、`use_policy = low_weight`，融合时降权。

理由：比幅与干涉测向在两个同频信号功率**接近**时会指向能量质心；差得远时弱信号只是被淹没，
不是「指偏」。**第 ③ 条不能省**——初版写成「对方 ≥ 本方 − separation 且 对方 ≥ 本方」，
化简后就是「对方更强」，那道闸等于不存在：`demo-03` 上 1800 行报了 1200 行混叠，
连电平相差 15 dB 的突发源都算了进去。

### 1.4 质量分档 DF-Q

`σ_total < 2° → DF-Q1`；`< 5° → DF-Q2`；`< 15° → DF-Q3`；`< 45° → DF-Q4`；否则 `invalid`。
**只看 σ 不看信噪比**：信噪比已经进了 σ，再判一遍等于把同一个量算两次
（emcore 的 `dfQuality(snr, σ)` 是双判据，这里有意简化）。

### 1.5 实测（原型阶段验证值，macOS）

| 判据 | 结果 |
|---|---|
| 蒙特卡洛 1e4 次 @ SNR 20 dB：经验 σ 对预算 σ | 1.81448° 对 1.8°，相对差 **0.80%**（线 3%）|
| `demo-03` 三站三源 20 s、1800 行：\|误差\| ≤ 3σ 占比 | **99.56%** |
| 同上：归一化误差的样本方差 | **1.0225**（线 [0.9, 1.1]）|
| 同上：归一化误差均值 | **+0.0174**（线 ±0.0707 = 3/√n）|

## 2. `ToaEstimator`：到达时间（EM-S-07）

隐含节点：用户不选、不配参数，编译器只在多站定位启用且方法含时差时自动接上——
时差定位的到达时间只应该有一种口径，暴露成槽位只会让人以为可以换。

```
σ_pick = 1/(2π·B·√max(SNR_lin,1))      B = 本站的实际采样率
σ_total = √(σ_pick² + σ_floor² + σ_sync² + σ_rxdelay²)
toa    = 真值时延 + (bias_ns + rx_delay_ns)·1e-9 + σ_total · N(0,1)
```

**与 emcore 的一处有意差别**：相关带宽取**站的实际采样率**，emcore 写死 10 MHz。
写死常数会给出与配置无关的假精度——500 kS/s 与 20 MS/s 的时差精度差 40 倍。
emcore 的原式保留在 `geo::legacy::toa_sigma_s()`，**只为守黄金基准**（D-009）。

**站钟全部来自场景 `sites[].clock`；缺 `clock` 即拒绝运行**，不默认一个完美时钟——
默认 0 ns 会让时差定位的结果好得不真实（铁律 15）。
在 `time.basis = LogicalSim` 下这些是**建模的**同步误差，不是任何真实设备的时统指标；
真实站钟与卫星驯服属 05 P2 的 `DeviceStatus`。

**已知简化**：同步误差按**每份报告独立重抽**，而真实的钟差是缓变的。
对协方差没有影响（求解器同样假定独立），但它意味着本模型不能用来研究钟差的时间相关性。

**必须写明的一条**：M2 的 σ_pick 是解析式，与采样率的关系是模型给的，不是仿真出来的。
真正的 M3 相关法到达时间估计需要 IQ 相关；500 kS/s 下时差分辨率约 2 µs ≈ 600 m，
做不出有意义的时差定位，要做至少需要 10 MS/s 以上（05 P2）。

## 3. `MultiSiteLocator`：多站定位（EM-S-06 / EM-S-07）

一个组件一个下拉：`method ∈ {aoa, tdoa, aoa_tdoa}`。**纯函数式**——站址随报告走
（`BearingReport.site_lon/lat/alt_m`），不绑场景、不读场景文件。

### 3.1 误差椭圆的置信度

**2σ 椭圆在二维下的包含概率是 `1 − e⁻² = 86.47%`，不是一维的 95.4%。**
em-demo 的注释写「2σ (~95%)」是把一维置信搬到了二维。每行报告显式写
`ellipse.scale = "2sigma"` 与 `confidence = 0.8646647167633873`，免得下游再算错。

CEP 用 `0.5887·(σ_max + σ_min)`（RAND 近似，圆形下退化为 1.1774σ 即精确的 Rayleigh 中位数）。
**曾经写成 √trace 是错的**，emcore 靠蒙特卡洛散布校验才发现（EM-C-UAV 09 号方案 W4）——
所以本卡的每条判据都同时给解析锚点与统计校验。

### 3.2 解析锚点

| 用例 | 判据 | 实测 |
|---|---|---|
| AOA 两站正交交汇、各距 1 km、σ_θ = 1° | σ_pos = 1000·π/180 | **17.4532925 m** |
| 同上 | 2σ 半轴 = 2σ_pos | **34.906585 m** |
| 同上 | CEP = 1.1774·σ_pos | **20.5495 m** |
| TDOA 三站等边、源在质心 | 不加权 GDOP = √(8/9) | **0.9428090415820634** |

### 3.3 已知局限一：伪线性 AOA 估计器在近简并几何下协方差偏乐观

emcore 的几何分级 `aoa_geometry_grade` 按**最大**张角分档，**看不见「两条近乎平行的线 +
一条好线」**这种近简并配置：最大张角 51–90° 会被判成 fair 甚至 good，而真正决定交汇质量的是
那对近简并的线。目标越远两条线越平行、最大张角反而越大——**所以被判 good 的那批最差**。

`demo-03` 上实测：`uav-1` 有两站真方位差 3.2°，被判 good 的解 2σ 椭圆覆盖率只有 **45%**。

处置（铁律 10：记录不掩盖，不调参让它达标）：`aoa_geometry_grade` 一字不动（它是 golden 守着的
emcore 口径）；**另加**量 `min_crossing_angle_deg`（最小两两交会角，把测向线当无向直线折到 [0, 90]），
降级判据改用它（参数名本来就叫 `min_crossing_angle_deg`）。

**有效档与降级档的实测**（`demo-03`，600 个解）：

| 档 | 样本 | 真值落 2σ 椭圆内 | 经验 50% 半径 / CEP |
|---|---|---|---|
| 最小交会角 ≥ 15° 且无低权重站 | 200 | **87.0%**（理论 86.5%）| **0.920** |
| 降级档 | 400 | 80.5% | 1.238 |

三个目标的最小交会角中位数：`uav-1` 7.1°、`uav-2` 28.4°、`uav-3` 9.7°——
`demo-03` 的三角形边长 2.2 km 而目标飞在 1.5–3 km 外，交会角本来就偏小。

### 3.4 已知局限二：未标定的固定钟差是协方差表达不了的系统偏差

时差定位对站钟的**固定偏差**极其敏感，而误差椭圆只描述随机散布。

`demo-03` 的 `site-3` 有 `bias_ns = 20`（20 ns × c = 6 m 距离差）。实测 600 个解：

| 目标 | 系统偏差 | 原始 2σ 覆盖 | 扣掉系统偏差后 | GDOP 中位 |
|---|---|---|---|---|
| `uav-1` | 240.6 m | 0.0% | 11.5% | 7.10 |
| `uav-2` | 4.5 m | 66.0% | **87.5%** | 1.17 |
| `uav-3` | 4.4 m | 39.5% | **86.5%** | 1.39 |

`uav-2` / `uav-3` 扣掉偏差后正好落在理论值上——**协方差本身没问题**。
`uav-1` 另有原因：它途中最近处离 `site-2` 只有 423 m，源贴近某一站时双曲几何病态，
偏差被放大到 240 m。系统把这些解标成 `geometry_quality = poor`。

按**几何良好**那一档取：400 个解，扣掉系统偏差后 2σ 覆盖 **85.3%**，中位误差 5.5 m；
全部 600 个解的中位误差 **7.95 m**（2.2 km 基线 + 纳秒级站钟）。

### 3.5 两种时差加权：数值并列，不调参使其一致

| 口径 | 做法 | 迹比（经验 / 预测）|
|---|---|---|
| `correlated_reference`（缺省）| `R = c²(diag σ_i² + σ_0²·11ᵀ)`，法方程 `HᵀR⁻¹H` | **1.004–1.013**，自洽 |
| `independent_pairs`（emcore 现行）| 站对当独立，`w_i = 1/(c²(σ_i² + σ_0²))` | **0.755–0.915**，协方差**保守偏大** |

五种配置（3/4/5 站；拾取主导与同步主导各一）都试过，方向一致。
站数 ≥ 4 时 `independent_pairs` 的**估计本身**也略差（4 站实际迹 2.93 对 2.64），
因为它没用上噪声的相关结构。

> 设计初稿曾判断 `independent_pairs` 会「低估协方差、结果偏乐观」，实测方向相反。
> 两个口径都保留、数值都在这里，**不许调参让它们一致**（铁律 10）。11 报告 §11.3 第 1 条记了这次修正。

## 4. 移植与常数策略

| 来源（`C-UAV Model Demo/emcore/`）| 去处 | 黄金基准 |
|---|---|---|
| `src/core/geo.cpp` | `geo/fix_geometry.{h,cpp}` | `tests/golden/geo_fix.json`，43 组 |
| `src/models/locate_aoa.cpp` | `geo/locate_aoa.{h,cpp}` | `tests/golden/aoa_location.json`，6 + 42 组 |
| `src/models/locate_tdoa.cpp` | `geo/locate_tdoa.{h,cpp}` | `tests/golden/tdoa_location.json`，36 + 128 组 |

全部相对误差 ≤ 1e-9。**求解器改成平面坐标接口**（吃米不吃经纬度）：数学与投影解耦，
golden 走 `geo::legacy` 的 111320 常数投影回放，引擎侧走 `default_geodesy().to_enu()` 的严格 ENU，
一份数学两处用。这是 D-009 在本线的落地方式；`scripts/build-all.sh` 有一条守卫，
`legacy::` 只允许出现在 golden 回放与 `legacy_*.cpp` 里（造过违规实测拦得下来）。

**Python 第二实现**：`algos/reference/{aoa_fix,tdoa_fix}.py`，显式循环累加（D-046 ⑧）。
AOA 对拍 600 个解最大相对误差 **1.68e-12**；TDOA 的椭圆与 CEP **3.6e-16 / 4.7e-15**，
GDOP 单独定 1e-5 的容差——它要把落盘的经纬度换回站心平面，而参考自身的
ENU → 经纬度 → ENU 往返在 2 km 处丢约 1 cm，这是参考实现的坐标往返误差，不是算法差别。

## 5. 不做（05 的 P1 / P2 与后续）

阵列测向（MUSIC / 相位干涉，`ArrayIQStream`）；IQ 相关的真到达时间（`MultiSiteIQSet`）；
真实站钟与卫星驯服（`DeviceStatus`）；频差定位 EM-S-08；跨站关联 EM-S-11 与多假设
（本卡假定「同一 `emitter_id` 的报告属于同一目标」，即关联已知，多源同频时这是一个真实的简化）；
`TrackReport` 航迹滤波；NLOS 几何驱动的测向多径误差（等 D3）。
